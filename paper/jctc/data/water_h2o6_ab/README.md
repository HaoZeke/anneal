# Water hexamer code-only A/B: results

Results of the session that `scripts/water_h2o6_ab/` drives. A is the anneal
code at commit `36086e988c5a71c156ffcbde152bf321a6f5ef25` with the input layer
of `a_input_layer.patch`; B is the code at commit
`bc16d35cf13e71c2edaf343b80fd8c41368631d4`, built as it is. Four arms, a budget
of 4000 engine calls, seeds 0 to 191, one thread on one pinned core, serial,
one session of 34261 s, A and B back to back for every seed and arm with the
order of the pair flipped on odd seeds. Both builds ran on the same GFN2-xTB
engine.

## Files

| file | content |
| --- | --- |
| `runs.csv` | one row per job: 192 seeds, 4 arms, 2 builds |
| `external_manifest.csv` | relative path, sha256, size in bytes, row count and a one-line description of every frame-level table that is kept outside git |
| `inputs.csv` | name, size and sha256 of every input, binary and library of the session |
| `inputs/` | the start geometry and the three references of the session, the references in their original atom order, and the sha256 of each |
| `meta.json` | settings of the session |
| `summary.md` | the output of `analyze.py` on the two CSV files and the per-seed table of the earlier record |
| `preflight.txt` | finite-difference table of the engine buffer and short runs of both builds with both buffer signs, run before the session |
| `diagnostics/b_seed83.txt` | one rerun of build B on seed 83 after the session, to see why its session row has one call; it replaces nothing |
| `controls/` | CREST controls run after the session, one directory per control with its `controls_runs.csv`, and `summary.md` |

## Files kept outside git

The frame-level tables are not in git: `crest_frames.csv`, with one row per
CREST frame of the `crest` and `crest_fair` arms, and the `controls_frames.csv`
of every control directory. `external_manifest.csv` lists each of them with its
relative path, sha256, size in bytes, number of data rows and a one-line
description. The files are published on the HaoZeke/anneal-paper-data dataset
under `water_h2o6_ab/`, each named `<sha256>-<basename>`. The two controls
without frames, `noise-0.3` and `noise-0.6`, have the same table of a header
line only, and so the same name.

`summary.md` and `controls/summary.md` are regenerated from the files of this
directory and the frame tables of the manifest with, in this directory,

```
python scripts/water_h2o6_ab/analyze.py --runs runs.csv --manifest external_manifest.csv \
    --external-dir <local directory with the published files> \
    --reference-energy -829.852228 --old-perseed ../water_v45b/water-v45b-perseed.csv \
    --old-receipts ../water_v45b/rerun-9a30f319/crest
python scripts/water_h2o6_ab/analyze_controls.py --manifest external_manifest.csv \
    --external-dir <local directory with the published files> controls/<directory> [controls/<directory> ...]
```

The scripts check the sha256 of every frame table against the manifest before
they read it, and stop when a file differs.

The reference energy is the energy written in the comment line of the prism
file of `../hq_sci_h2o6`; it is used only to count final energies within 1 meV
of it.

## Environment

* CPU: Intel Xeon (family 6, model 207), 8 virtual CPUs of a KVM guest, one
  core pinned for the session, Linux 6.12.113.
* Engine: rgpot GFN2-xTB library from rgpot revision
  `8efdd246322d1f32bc1bcbd7e5dfdd7a4237960e`, xtb 6.7.1; CREST 3.0.2.
* Toolchain: rustc 1.88.0, gcc 13.3.0, Python 3.12.3 with numpy 2.5.5 and
  scipy 1.18.1.
* One thread: `OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS` and
  the related variables are 1 for every child process.

The earlier record of the panel used tblite 0.7.0 as the GFN2 engine and an
input set that is not in the repository.

## Inputs

The receipts of the earlier record name a start file with sha256
`faaba2431950230f1c57c5bfed88889e2636ed05d5f8cd1ad142ccec8838c99a`. No commit,
branch or data directory of the repository holds a file with that hash, and the
reference files of the earlier record have no recorded hash. The inputs of this
session are therefore regenerated by `make_inputs.py`: the start geometry from
the `reference_coordinates` template of `src/catalog/molecular.rs` (six waters,
3.0 A apart along x), and the prism, cage and book references from
`best_h2o6_eindir_s0.xyz`, `best_h2o6_eindir_s6.xyz` and
`best_h2o6_eindir_s3.xyz` of `../hq_sci_h2o6`, with every water written as O, H,
H. The prism file was already in that order; the cage and book files list a
hydrogen after the oxygen of another water, and `inputs/original_order/` holds
the three files as they are. The smallest IRA RMSD between two of these
references is 1.1970 A (prism and book), so the gate is 0.598496 A; the earlier
record used 0.784112 A. Because the earlier inputs are not recovered, the
input-only comparison was not run.

The files of `scripts/water_h2o6_ab/` that the session used (`make_inputs.py`,
`run_ab.py`, `polish.py`, `preflight.py`, `sign_check.py`, `engine_shim.c`,
`crest_driver.c`, `a_input_layer.patch`) are as committed, with two exceptions
that do not change what runs: the source of the driver used in the session
named two local pointer variables differently, and a sentence of the docstring
of `make_inputs.py` was corrected. `analyze.py`, `controls.py` and
`analyze_controls.py` are not part of the session: they read its results or run
after it. The binary built from the committed
driver source with the command of the harness README is byte-identical to the
one of the session (`crest_driver` in `inputs.csv`), and so is the shim.

## Controls

Every control starts CREST from a given geometry, scores the first 180 frames
of each run with both builds against the references, and times nothing. Each has
24 runs, indices 0 to 23.

| directory | start of CREST | engine | reference orderings |
| --- | --- | --- | --- |
| `chain-driver` | start geometry of the A/B | GFN2-xTB through the call server, 4000 calls | as used, original, shuffled |
| `chain-native` | start geometry of the A/B | built-in GFN2 of CREST | as used |
| `noise-0.05` | start geometry of the A/B, every coordinate displaced by a Gaussian of 0.05 A | call server | as used |
| `noise-0.3`, `noise-0.6` | the same with 0.3 A and 0.6 A | call server | as used |
| `packed-3.0`, `packed-4.5` | six waters at random, centres inside a sphere of radius 3.0 A and 4.5 A | call server | as used |
| `prism-start`, `cage-start`, `book-start` | the reference isomer | call server | as used, original, shuffled |

The runs of `noise-0.3` and `noise-0.6` all stop in CREST at its check of the
bonding of the start and have no frames, and so does run 3 of `noise-0.05`;
they are counted as failed in `controls/summary.md`.

## Notes

* The CSV files were written with CR LF line ends by the harness and are
  committed with LF line ends; nothing else in them is changed.
* CREST is not seeded. For the `crest` and `crest_fair` arms the A run and the B
  run of a seed are independent draws, and the same CREST frames are scored by
  both builds in the cross columns of `crest_frames.csv`.
* The row of build B for seed 83 has one call in `anneal` and `polish_fair`; see
  `diagnostics/b_seed83.txt`. It is counted as a miss and was not rerun.
* Build A is slow in some runs, with about three times the time per engine call
  of its other runs; the same seeds recur in `anneal` and `polish_fair`, see the
  table of slow runs in `summary.md`.
