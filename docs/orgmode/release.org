#+TITLE: Release process

A PyPI, crates.io, or GitHub Release upload happens only when a
=vX.Y.Z= tag is pushed. That is the entire publish gate.

* Tag name

=.github/workflows/release.yml= listens for =push.tags: 'v*'=. The
publish jobs also require =startsWith(github.ref, 'refs/tags/v')=.

- Correct: =v0.9.0=, =v0.7.2=
- Wrong: =0.8.0=, =release-0.9.0=, a branch named =v0.9.0=

An unprefixed tag such as =0.8.0= is a Git object only. It does not
start the workflow, so it does not upload wheels, does not publish
=anneal-core=, and does not open a GitHub Release.

Leave a mistaken unprefixed tag in place. Add the =v= tag on the same
commit. Do not move or delete the old name.

* Version

The handwritten package version is =[package].version= in the workspace
=Cargo.toml=. Edit that one line, then run cogapp
(https://nedbatchelder.com/code/cog/) from the repository root:

#+BEGIN_SRC bash
python3 scripts/version_cog.py -r @scripts/cogfiles
python3 scripts/version_cog.py -d -o .zenodo.json packaging/zenodo.cog
#+END_SRC

That refreshes =pyproject.toml=, =pixi.toml=, =meson.build=,
=CITATION.cff=, =include/anneal-version.h=, the README badge, and
=.zenodo.json=. The Zenodo creators come from =CITATION.cff=.
CMake, Sphinx, and the Rust crate read the field
themselves. CMake records =Cargo.toml= in =CMAKE_CONFIGURE_DEPENDS=
so an existing build directory reconfigures after a bump.
=cargo update --workspace --offline= refreshes the =anneal-core= entry in =Cargo.lock=
(https://doc.rust-lang.org/cargo/commands/cargo-update.html).
Towncrier (https://towncrier.readthedocs.io/en/stable/)
reads the field through =scripts/anneal_version.py=. Do not write a version
into =towncrier.toml=, and do not edit =CHANGELOG.md= by hand.
Contributor notes stay in =docs/orgmode/= and are exported with
=emacs --batch -l docs/export.el=.

=cog bump= (https://docs.cocogitto.io/) does not rewrite
=CHANGELOG.md= (=disable_changelog = true=).
Its pre-bump hook sets the workspace version, restamps the generated
copies, refreshes =Cargo.lock=, runs towncrier
(https://towncrier.readthedocs.io/en/stable/), and runs the drift checks
before the bump commit.
Its post-bump hook runs the drift checks again.

=validate-release= reads the workspace manifest, =pyproject.toml=, and
=CITATION.cff=, and requires them to equal the tag with the leading
=v= stripped. It also runs =python scripts/version_cog.py --check @scripts/cogfiles=
(https://nedbatchelder.com/code/cog/) and =scripts/check_version_sot.py=. If any copy disagrees, the workflow
stops before wheels and nothing is published. The validate step uses
=set -euo pipefail= so a failed =test= fails the job.

* Steps

1. Add towncrier (https://towncrier.readthedocs.io/en/stable/) fragments
   under =docs/newsfragments/= for every user-visible change.
2. Edit the one version line in the workspace =Cargo.toml=.
3. Run =python3 scripts/version_cog.py -r @scripts/cogfiles= and
   =python3 scripts/version_cog.py -d -o .zenodo.json packaging/zenodo.cog=
   (https://nedbatchelder.com/code/cog/), then
   =cargo update --workspace --offline= so =Cargo.lock= matches.
   =cog.toml= is the cocogitto
   config (https://docs.cocogitto.io/), so this step does not call a
   bare =cog=.
4. Run =pixi r towncrier-build= so =CHANGELOG.md= carries that version.
5. Run =python3 scripts/version_cog.py --check @scripts/cogfiles= and
   =python3 scripts/check_version_sot.py= so a drifted copy stops the
   release before the commit.
6. Commit. Push =main=.
7. Create an annotated, signed tag named *exactly* =vX.Y.Z= on that
   commit (the same object the changelog describes, not a later
   campaign commit):

#+BEGIN_SRC bash
git tag -a vX.Y.Z <commit> -m "vX.Y.Z"
git push origin vX.Y.Z
#+END_SRC

8. Confirm the =Release= workflow on that tag is green and that
   https://pypi.org/project/anneal/X.Y.Z/ exists.

Do not use =workflow_dispatch= as a substitute for the tag. Dispatch
builds artifacts; it does not publish unless =github.ref= is a =v*= tag.

* What the tag starts

On =vX.Y.Z= the workflow builds abi3 wheels, an sdist, and native
library tarballs, then publishes the Python artifacts to PyPI, publishes
=anneal-core= to crates.io if that version is absent, and opens the
GitHub Release.

* Why 0.8.0 and 0.9.0 were missing from PyPI

PyPI and crates.io stopped at =0.7.2= (=v0.7.2=, 2026-08-01).

- =0.8.0= (2026-08-08) was tagged =0.8.0=, not =v0.8.0=. The workflow
  never ran. That commit also left =CITATION.cff= at =0.7.2=, so a
  later =v0.8.0= on the same tree still fails =validate-release=.
- =0.9.0= had matching =0.9.0= metadata and assembled notes
  (=df28dd2=) and no tag at all.

The corrective tags are =v0.8.0= on =0.8.0= and =v0.9.0= on
=df28dd2=. The =0.8.0= tree's workflow file does not =set -e= in
validate, so that historical tag can still build wheels even though
=CITATION.cff= is =0.7.2=. New tags use the =set -euo pipefail=
validator.
