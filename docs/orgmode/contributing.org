* Conventional Commits

Commit messages follow the Conventional Commits convention.
CI checks them with cocogitto (https://docs.cocogitto.io/).
That program is separate from cogapp (https://nedbatchelder.com/code/cog/), which regenerates version copies.
Use the standard prefixes:

- =feat:=   new functionality
- =fix:=    bug fix
- =docs:=   documentation only
- =refactor:= behaviour-preserving code change
- =chore:=  tooling, build, dependency updates
- =ci:=     CI configuration

* Version

The only handwritten package version is =[package].version= in the workspace =Cargo.toml=.
Edit that one line, then regenerate the copies from the repository root:

#+BEGIN_SRC bash
python3 scripts/version_cog.py -r @scripts/cogfiles
python3 scripts/version_cog.py -d -o .zenodo.json packaging/zenodo.cog
#+END_SRC

=scripts/version_cog.py= calls cogapp (https://nedbatchelder.com/code/cog/) with one shared prologue.
It refreshes =pyproject.toml=, =pixi.toml=, =meson.build=, =CITATION.cff=, =include/anneal-version.h=, the README badge, and =.zenodo.json=.
The Zenodo creator list is read from =CITATION.cff=.
=cog.toml= belongs to cocogitto (https://docs.cocogitto.io/), so this step does not call a bare =cog=.
CMake, Sphinx, and the Rust crate read the same field when they configure or compile.
=cargo update --workspace --offline= refreshes the =anneal-core= entry in =Cargo.lock= (https://doc.rust-lang.org/cargo/commands/cargo-update.html).
Towncrier (https://towncrier.readthedocs.io/en/stable/) reads the field through =scripts/anneal_version.py=.
Do not write a version into =towncrier.toml=.

* Changelog (towncrier)

Changelog notes are assembled with towncrier (https://towncrier.readthedocs.io/en/stable/) from news fragments.
Do not edit =CHANGELOG.md= by hand.
The org sources under =docs/orgmode/= are exported to RST by =emacs --batch -l docs/export.el=; write contributor notes there, not in generated RST.
For any user-visible or breaking change, add a fragment under =docs/newsfragments/= before merging the PR:

- Name: =+short-desc.type.rst= (or =123.type.rst= for PR #) where type is one of: added, changed, removed, fixed, deprecated, security, dev, misc.
- Content: one or more lines describing the change (towncrier, https://towncrier.readthedocs.io/en/stable/, adds the bullet and wires the issue link from filename when numeric).

Preview/build locally (requires the uv feature or uv on PATH):

#+BEGIN_SRC bash
pixi r towncrier-draft   # preview, no write
pixi r towncrier-build   # write to CHANGELOG.md and consume fragments
#+END_SRC

Run the build step as part of preparing a release tag, after the one-line version edit and cogapp (https://nedbatchelder.com/code/cog/).
Fragments are required for changes that should appear in release notes.

The publish tag must be named =vX.Y.Z=. An unprefixed tag does not
start =.github/workflows/release.yml= and does not upload to PyPI.
See [[file:release.org][Release process]].

* Style

Rust code is formatted with =cargo fmt= and linted with =cargo clippy --all-features -- -D warnings=.
Python code follows =ruff=.

* Tests

Rust tests under =tests/= and =benches/=; Python tests under =pytest/=.
The full pixi-driven matrix is what CI exercises.
