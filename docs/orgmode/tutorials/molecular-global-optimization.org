* Find the Ground State of an EON Structure

Atomistic workflows minimize.
ASE relaxes structures with L-BFGS and FIRE. eOn (TheochemUI/eOn on GitHub)
minimizes structures stored as EON =.con= files, and it can drive a potential
that rgpot serves over RPC.

Goswami, Gunde, and Jónsson, Front.
Chem. (2026),
doi:10.3389/fchem.2026.1807063, is the enhanced climbing-image NEB paper for saddle searches on this stack. eOn, which runs those bands, is the Zenodo record doi:10.5281/zenodo.18529495.

L-BFGS and FIRE are /local/ minimizers: they walk downhill to the nearest
minimum.
The nearest minimum is often not the one you want.
This tutorial runs a local minimizer and two global minimizers, scipy's
=dual_annealing= and =anneal='s portfolio, from one disordered start on a 7-atom
Lennard-Jones cluster (reduced units, global minimum =-16.505384=).
With anneal 0.11.1 from PyPI, =tests/ase_vs_anneal.py= gives:

| Minimizer                       | Final energy | Evaluations                       |
|---------------------------------+--------------+-----------------------------------|
| ASE L-BFGS (local), 500 steps   |   -10.751101 | 500 force steps                   |
| scipy ~dual_annealing~ (global) |   -16.505377 | 17003                             |
| ~anneal~ portfolio (global)     |   -15.593204 | 10911 evaluations, 2222 gradients |

L-BFGS stops at its step limit in a basin above the global minimum. scipy's
=dual_annealing= reaches the global minimum.
The =anneal= 0.11.1 portfolio ends below the local result and above the global
minimum, so the script prints =RESULT: FAIL=.
The script checks that =anneal= reaches the global minimum within 0.05 and does
no worse than scipy.
The =anneal= result depends on the =anneal= version you build or install.

- [[https://pixi.sh][pixi]] (manages the toolchain)
- The =anneal= and =readcon= Python modules: installed in the =rpctest=

** Step 1: drive an rgpot potential from Python

The in-process calculator is =rgpot.ase.RgpotCalculator=.
The Cap'n Proto calculator is =rgpot.ase.RgpotRpcCalculator=.
It talks to the same =potserv= RPC server the eOn client connects to, so Python
and eOn evaluate the same energies and forces.
The old =ase_calculator.RgpotCalculator= import warns and re-exports it.
Point the RPC calculator at a potential and it launches the server:

#+attr_rgpot: compile needs a potserv path
#+begin_src python
import numpy as np
from ase import Atoms
from rgpot.ase import RgpotRpcCalculator

calc = RgpotRpcCalculator.spawn(server_bin="path/to/potserv", potential="LJ")

start = np.random.RandomState(1).uniform(-2.3, 2.3, size=(7, 3))
atoms = Atoms(numbers=[0] * 7, positions=start, cell=[40, 40, 40])
atoms.calc = calc

print("start energy:", atoms.get_potential_energy())   # 19.8379
#+end_src

Use =spawn= as a context manager (~with RgpotRpcCalculator.spawn(...) as calc:~)
to stop the managed server on exit.

** Step 2: local relaxation stops at the nearest minimum

#+attr_rgpot: compile continues Step 1
#+begin_src python
from ase.optimize import LBFGS

LBFGS(atoms).run(fmax=1e-3)
print("local L-BFGS energy:", atoms.get_potential_energy())   # -12.3029
#+end_src

Without a step limit, L-BFGS converges in 721 steps to a minimum at -12.3029,
not the global one.
The LJ7 global minimum, the pentagonal bipyramid at =-16.505384=, sits in a
different basin; from this start a local minimizer does not cross into it.

** Step 3: search for the global minimum

=AnnealRunner= wraps =anneal='s portfolio optimizer (the method of the INFORMS
Journal on Computing paper: Thompson-allocated basin hopping, differential
evolution, generalized simulated annealing, parallel tempering, GLE-Langevin)
behind =run()=.
It is not an =ase.optimize.Optimizer=.
=AnnealOptimizer= is the deprecated name.
It uses the rgpot forces as the gradient:

#+attr_rgpot: compile needs the anneal module and continues Step 2
#+begin_src python
from rgpot.ase import AnnealRunner

atoms.set_positions(start)              # back to the disordered start
opt = AnnealRunner(atoms, budget=15000, seed=11, pad=3.0)
opt.run()
print("anneal energy:", opt.get_potential_energy())   # -15.5331 with anneal 0.11.1
print("evaluations:", opt.nevals)                     # 13249 with anneal 0.11.1
#+end_src

With anneal 0.11.1 this run ends at -15.5331, below the local result and above
the global minimum.
=scipy.optimize.dual_annealing= reaches -16.505377 from the same start in =tests/ase_vs_anneal.py=.
=tests/ase_vs_anneal.py= runs all three side by side.
When to pick a local or a global minimizer is in
[[file:../explanation/global-optimization.org][Local and global minimization]].

** Step 4: start from a =.con= file

EON workflows start from a structure on disk.
=atoms_from_con= reads an EON =.con= file into =ase.Atoms= through
=readcon-core= -- the files eOn reads and writes.
It is in =CppCore/rgpot/rpc/ase_helpers.py=; put =CppCore/rgpot/rpc= on
=PYTHONPATH= to import it:

#+attr_rgpot: compile needs a potserv path, the readcon module and tiny_cuh2.con
#+begin_src python
from ase_helpers import atoms_from_con
from rgpot.ase import RgpotRpcCalculator

calc = RgpotRpcCalculator.spawn(server_bin="path/to/potserv", potential="CuH2")
atoms = atoms_from_con("tiny_cuh2.con", calc=calc)
print(atoms.get_chemical_symbols())          # ['Cu', 'Cu', 'H', 'H']
print("energy:", atoms.get_potential_energy())   # -6.474709

# The cell comes from the .con; override it with a larger box when needed.
atoms = atoms_from_con("tiny_cuh2.con", cell=[15, 20, 30], pbc=False)
#+end_src

Relaxing it is the same =run()=: rattle the structure, then walk it back to the
minimum the =.con= recorded:

#+attr_rgpot: compile continues the block above
#+begin_src python
from ase.optimize import LBFGS

atoms.calc = calc
atoms.rattle(stdev=0.15, seed=1)
LBFGS(atoms).run(fmax=0.02)
print("relaxed energy:", atoms.get_potential_energy())   # back to -6.474709
#+end_src

=tests/con_relax_demo.py= runs this round-trip.

** Visualize the minimization on the (s, d) landscape

Two complementary views.
First, sample the surface densely: a probe atom moved through the x-y plane near
a lone atom (a shallow well) and a bound pair (a deeper well) gives a 2D
Lennard-Jones double well.
ASE LBFGS started in the shallow basin stops there; anneal's portfolio reaches
the deep one.
=pes-double-well= runs
=tests/pes_double_well.py= and writes =docs/orgmode/_static/pes_double_well.png=.

#+attr_rgpot: syntax
#+begin_src bash
pixi run -e rpctest pes-double-well
#+end_src

#+CAPTION: rgpot LJ double well (densely evaluated 2D PES). ASE LBFGS (red) stops in the shallow left basin at -2.0; anneal's global portfolio (orange star) reaches the deep right basin at -3.0.
[[file:../../orgmode/_static/pes_double_well.png]]

Second, for an EON minimization, ``rgpycrumbs eon plt-min`` renders the actual
trajectory on a gradient-enhanced 2D landscape: progress ``s`` toward the
minimum against lateral deviation ``d``, with the energy surface fitted from the
path.
``tests/eon_min_landscape.py`` runs ``eonclient`` LJ7 minimizations and plots
the lowest one (energies capped with ``plt-min --energy-cap-window`` so the
colorbar resolves the well):

#+attr_rgpot: syntax
#+begin_src bash
pixi run -e eonviz eon-min-landscape
#+end_src

#+CAPTION: An EON LJ7 minimization on the (s, d) landscape: the path descends from the start (initial) to the minimum eonclient reached (minimized), and the surface energy is shown relative to that minimum.
[[file:../../orgmode/_static/eon_min_landscape.png]]

** Where to go next

- Swap ~potential="LJ"~ for =CuH2=, =XTB=, =TBLite=, or =Metatomic:<model>= (for
example a PET-MAD model); the calculator stays the same, only the server backend
changes, and the same server serves eOn.
=XTB=, =TBLite= and =Metatomic:<model>= need a =potserv= built with
=with_xtb=, =with_tblite= or =with_metatomic=.
- Read [[file:../howto/integration.org][External Integration Guide]] for how eOn
links rgpot's RPC server from C++.
- Read
  [[file:../howto/eindir-anneal.org][rgpot potentials as eindir objectives]]
for how an rgpot potential becomes an =anneal= objective with no glue code.
