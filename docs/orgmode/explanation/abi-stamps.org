* ABI stamps

rgpot carries compatibility numbers that are separate from its package version.
This page explains what each one covers and why it exists.
The functions and macros are listed in the
[[file:../reference/c_abi.org][C ABI reference]].
The steps to change each number are in
[[file:../contributing/developer/abi-bump.org][Bump the ABI numbers]].

** The C ABI stamp

=rgpot-core/include/rgpot.h= carries two identities.
The package version (=RGPOT_VERSION= and its parts) follows the crate.
The ABI stamp (=RGPOT_ABI_VERSION_MAJOR=, =RGPOT_ABI_VERSION_MINOR=,
=RGPOT_ABI_LAYOUT_REVISION=) follows the layout of the exported structs and the
signatures of the exported functions.
A release that changes no exported symbol leaves the stamp where it is.

A consumer that loads the library at run time compares the stamp it compiled
against with =rgpot_abi_stamp()= of the library it loaded, or passes its own
stamp to =rgpot_abi_compatible()=.
The major number moves for a change an old caller cannot survive.
The minor number moves for an addition that leaves every old call valid, so a
library with a higher minor still serves an older caller.
The layout revision moves when an exported struct changes size, field order or
field type; callers and libraries with different layout revisions never match.

The stamp is not an ELF soversion.
In a Meson build with =with_rust_core=, =librgpot= links the static archive
=librgpot_core.a= and keeps only the archive members it references.
The cdylib
=librgpot_core.so= that cargo builds next to it exports the whole C ABI, and the Meson test =abi_core_symbols=
checks that library.

** Scope

The C ABI stamp covers =rgpot.h= only.
Other interfaces carry their own numbers:

- the C++ classes that cross the =librgpot= boundary: the layout stamp below and
  the soversion =kCxxSoversion=;
- the eindir objective that =rgpot_potential_t= embeds:
  =rgpot_eindir_abi_stamp()= and =rgpot_eindir_abi_compatible()=, which report
  and check the stamp of the =eindir-core= compiled into the library;
- the neighbour query: =RGPOT_NLIST_ABI= in =CppCore/rgpot/nlist/rgpot_nlist.h=;
- the plugin interface: =RGPOT_PLUGIN_API_VERSION= in =include/rgpot/plugin.h=;
- the engine libraries:
  =RGPOT_ENGINE_ABI_VERSION= in =CppCore/rgpot/engine_c_abi.h=;
- =librgpot_mpi=: =RGPOT_MPI_ABI_VERSION= in
  =CppCore/rgpot/calculator_mpi_abi.h=, with its own soversion 3.

The engine plugins (for example
=libclassical_engine.so= and =libmopac_engine.so=) are built without a soversion
and opened by those unversioned names.
Each plugin reports =RgpotEngineAbiStamp=
(=RGPOT_ENGINE_ABI_VERSION=, =RGPOT_ENGINE_ABI_MINOR=,
=RGPOT_ENGINE_ABI_LAYOUT_REVISION=) through =rgpot_engine_abi_stamp=, or is
minor 0, layout 1 when that symbol is absent.
Because engine minor bumps add optional exports that the host probes with
=dlsym= (such as
=rgpot_engine_last_components= and =rgpot_engine_component_name= in minor 5),
the Rust loader's =RgpotEngineAbiStamp::serves(host)= accepts any plugin with
the same major and layout revision whose minor is at most the host's
(=ENGINE_ABI_MINOR=), resolving optional exports only when present and reporting
them as absent otherwise, while rejecting plugins whose minor is newer than the
host's.

** The C++ layout stamp

The header-only C++ classes are a second boundary.
A consumer compiles =Potential=, the force structures and the pair potentials
from the headers, and the library supplies their out-of-line members.
A library built from another revision of those headers, or with another value of
=RGPOT_HAS_CACHE=, has the same C stamp and still runs with the wrong member
offsets or the wrong vtable.
=CppCore/rgpot/abi/CxxLayout.hpp= stamps that boundary.
It needs neither =rgpot.h= nor the Rust core.

The stamp is the C struct =rgpot_cxx_layout_stamp_t= with =revision=
(=kCxxLayoutRevision=), =features= and a 64-bit =hash=.
=rgpot::abi::header_stamp()= is a =constexpr= of the header: the stamp the
consumer compiled against.
=rgpot::abi::library_stamp()= calls the exported =rgpot_cxx_layout_stamp()=: the
stamp of the loaded library.
=rgpot::abi::layout_compatible()= is true when revision, feature bits and hash are equal; =rgpot_cxx_layout_compatible()=
is the same check for a caller that holds only the C struct, and returns 0 for
NULL.

#+attr_rgpot: run link=rgpot
#+begin_src cpp
#include <cstdio>

#include "rgpot/abi/CxxLayout.hpp"

int main() {
  if (!rgpot::abi::layout_compatible()) {
    std::fprintf(stderr, "librgpot was built from other C++ layouts\n");
    return 1;
  }
  return 0;
}
#+end_src

The hash folds =kCxxLayoutRevision=, the feature bits, the sizes of =void *= and
=std::size_t=, and the =sizeof= and =alignof= of each covered type.
For the plain structures it also folds the =offsetof= of each field, and for the
enumerations the values consumers switch on.
For the polymorphic classes it folds the number of virtual functions, because a
vtable change does not show in =sizeof=.
Feature bit 0 is =RGPOT_HAS_CACHE=, which adds the virtual =setCache= to
=PotentialBase=.

Covered types:

- =ForceInput=, =ForceOut=, =ForceBatch=, =PotCaps=, =CalculatorGroup=
- =LJConfig=, =LJClusterConfig=, =MorseConfig=, =ZBLConfig=, =SuttonChenConfig=,
  =D2Config=, =D2CpmdConfig=, =D4Config=
- =Reentrancy= and =PotType=
- =PotentialBase=, =Potential<Derived>= (through one probe instantiation),
  =LJPot=, =LJClusterPot=, =MorsePot=, =ZBLPot=, =SuttonChenPot=, =SumPot=,
  =lr::SumPot=, =D2Pot=, =D2CpmdPot=
- with the cache: =cache::EvalCounts= and =cache::PotentialCache=

The classes of the optional backends are not covered (xtb, tblite, dftd3, dftd4,
ExprPot, XcKernel, Metatomic, UMA, NWChem, CPMD, MOPAC, Skala, the Fortran
potentials).
=D4Config= is covered, because it sits in a header of its own that does not
include dftd4; =D4Pot= is not.
Their headers and features differ between builds, so a stamp over them would
refuse libraries that agree on everything a consumer uses.

The hash depends on the platform: operating system, architecture, standard
library and data model form the tag =kCxxPlatformTag=.
=kCxxSoversionTable= records the no-cache hash of each platform that CI builds,
and =CppCore/rgpot/abi/cxx_soversion_ledger.txt= records a platform-independent
fingerprint of the stamp's inputs for each soversion.
=kCxxSoversion= is the ELF soversion of =librgpot=, read by Meson and CMake; it
is not the hash.

** History

| Release | =rgpot.h= stamp | =librgpot= soversion |
|---------+-----------------+----------------------|
| 3.5.0   | 1, 0, 1         | 3                    |
| 3.5.1   | 1, 0, 1         | 4                    |
| 3.6.0   | 1, 1, 1         | 6                    |
| 3.7.0   | 1, 2, 1         | 6                    |
| next    | 1, 6, 1         | 9                    |

3.6.0 raised the minor for =rgpot_eindir_abi_compatible=; a caller built against
minor 0 still matches it.
3.7.0 raised the minor to 2 for the Hessian-vector functions.
They are additions, and their state lives behind the
=fused_cache= pointer of the handle, so =rgpot_potential_t= keeps its layout and
the layout revision stays at 1.
A 3.7 library still serves a caller built against minor 0 or 1.
A caller built against minor 2 is refused by a 3.6 library.
The next release raises the minor to 3 for
=RGPOT_SCC_NOT_CONVERGED=, =rgpot_set_last_error= and the fused-cache settings
and error kind.
They are additions, no old call changes, and the layout revision stays at 1.
The next release also raises the minor to 4 for the Taylor jet functions and the
statuses =RGPOT_NO_JET= (6), =RGPOT_JET_BRANCH= (7) and =RGPOT_JET_DOMAIN= (8).
The jet callback also lives behind =fused_cache=, so the layout revision stays
at 1.
It also raises the minor to 5 for the engine and RPC Hessian-vector interfaces.
It raises the minor to 6 for =rgpot_potential_new_eam_table= and the four
=RGPOT_EAM_TABLE_*= format codes.
They are additions that take no new struct, so the layout revision stays at 1.

The ledger notes that soversion 3 was the 3.4.0 layout, which 3.5.0 reused after
the layout changed, and that 4 is the 3.5.0 layout, shipped from 3.5.1.
Soversion 5 recorded =LJPot= and =MorsePot= gaining a neighbour list and a
cached pair table.
Soversion 6 drops the copied half-list from LJ and Morse and gives ZBL and the
open Lennard-Jones cluster a neighbour list.
A program linked against soversion 4 does not load =librgpot.so.6=.

Soversion 9 stamps =SumPot=, =lr::SumPot= and =PotType::LrSum=.
=lr::SumPot= derives from =SumPot= now, so it grows from 56 to 120 bytes and its
old constructor and =add= symbols leave the library.
It also stamps =D2Config=, =D2Pot= and =PotType::D2=.
It also stamps =D2CpmdConfig=, =D2CpmdPot= and =PotType::D2Cpmd=.
=D4Config= gains =periodic= in the padding after =atm=, so it keeps its size and
only the field offsets show it.
=D2CpmdConfig= gains =symmetry=.
A program linked against soversion 8 does not load =librgpot.so.9=.
