#+TITLE: Method Composition
#+OPTIONS: ^:nil

One narrative walk of a cooperative Lennard-Jones cluster run, naming
each mechanism from [[file:catalog.org][catalog.org]] as it appears. The walk follows
=examples/lj_cluster_search.rs='s =run_capnp_catalog= function
(examples/lj_cluster_search.rs:4038-6741). Catalog mode, or a set
catalog endpoint, calls it (examples/lj_cluster_search.rs:2489). That
call is built with the =bank-rpc= feature. The function drives
=anneal_core::methods::cluster_hopping::run_with_bias_at_checkpoints=
(src/methods/cluster_hopping.rs:3369).

* Start: configuration and identity

A replica reads its run name, ensemble, and replica id from the
environment (examples/lj_cluster_search.rs:4072-4086) and computes the
LJ system's canonical =SystemSignature= via
=crate::catalog::lj::system_signature= (src/catalog/lj.rs:163) and its
=DescriptorSpace= via =crate::catalog::lj::descriptor_space=
(src/catalog/lj.rs:140). A =CooperativeRun= is constructed for the
single local replica with its charged-work budget
(examples/lj_cluster_search.rs:4090-4094). If an endpoint is given, a
=CatalogClient= connects under the =CatalogIdentity= and attaches to
the run (examples/lj_cluster_search.rs:4098-4121). A refused or
unreachable coordinator leaves local execution active rather than
failing the run.

Runtime configuration is a clone of the caller's =Config=
(=run_cfg=, examples/lj_cluster_search.rs:4266). The acceptance law is
copied from that config: =budget_window= is not forced on
(examples/lj_cluster_search.rs:4281). =polish_records= is set to one
full quench, =relax_steps=
(examples/lj_cluster_search.rs:4437-4442). Two cooperative extensions
are environment-controlled. The SOAP packing archive is fed from remote
minima unless =CATALOG_COOP_WELLS= is =0=
(examples/lj_cluster_search.rs:4324-4329), and only when the binary
includes the =featomic= feature. Remote minima are queued for this
chain's own bias only when =CATALOG_SHARED_BIAS= is =1=
(examples/lj_cluster_search.rs:4334).

* The hop loop

=run_with_bias_at_checkpoints= (src/methods/cluster_hopping.rs:3369)
drives the ordinary perturb-quench chain against a =BasinBias= keyed on
=ClusterFingerprint= (examples/lj_cluster_search.rs:4544), calling back
into the closure below every =checkpoint_interval= charged evaluations.
The default interval is 500, or ~CATALOG_SLICE~ / ~BANK_SLICE~
(examples/lj_cluster_search.rs:4443-4448). Inside each hop, before the
checkpoint fires:

- *Move selection*: the caller's =MoveLibrary= supplies the kernels
  (src/methods/cluster_hopping/moves.rs:112). =Config::recommended=
  selects =MoveLibrary::LeanBurst= at every size. An allocator chooses
  the arm when =allocate_moves= is on (catalog.org "learned allocation").
- *Screening*: the Bayesian cost-asymmetric screen and the quench
  predictor decide whether a partial relaxation is worth finishing
  (catalog.org "local search"); the return screen aborts trials
  heading straight back into the current basin.
- *Acceptance*: the Metropolis or budget-window temperature and the
  well-tempered basin bias jointly decide whether the quenched trial
  becomes the new live state. A tabu quarantine can refuse a return to
  a stalled funnel.
- *Stall response*: if the chain has gone longer without a lower
  minimum than its own longest prior quiet stretch, a soft-mode climb,
  symmetrise, path attempt, trail-on-stall, or restart-on-stall may
  fire, in the order the config flags set.

None of this loop body talks to the coordinator. It is the same code
path a solo run takes. The cooperative layer only enters at a
checkpoint boundary.

* Checkpoint: conversation with the coordinator

The closure passed as =checkpoint= (examples/lj_cluster_search.rs:4691)
receives a =ChainCheckpoint= (src/methods/cluster_hopping.rs:226), a
read-only snapshot of the live chain: current state, best state, and
every quench boundary and accepted transition since the last
checkpoint. It runs, in order:

1. *Charge the cooperative ledger.* Each quench boundary in the
   snapshot is recorded as =ChargeKind::BasinEscape=. Charged work that
   those boundaries do not cover is =AuxiliaryEvaluation=. A checkpoint
   with no charged work records an uncharged =LocalProposal=. One
   =CooperativeRun::record_work_batch= call writes the batch
   (examples/lj_cluster_search.rs:4906-4929). Executed transitions go
   through =CooperativeRun::record_executed_transition=
   (examples/lj_cluster_search.rs:4932-4946). This is
   =crate::cooperative_search::ledger::CooperativeLedger= (catalog.org
   "cooperative ledger and charge kinds"). The ledger is idempotent, so
   a retried checkpoint after a transient RPC failure does not charge
   the same work twice.

2. *Register local-topology evidence.* =adaptive_catalog_operations=
   (examples/lj_cluster_search.rs:7261) turns unadopted probe
   transitions into =RegisterCurrent=, =Adopt= and =Unresolved=
   operations, posted with =post_record_current= and
   =post_record_transition=
   (examples/lj_cluster_search.rs:4949-4996). The occupied minimum is
   sent only when it has changed
   (examples/lj_cluster_search.rs:4997-5016), because every registration
   asks the coordinator to validate it.

3. *Offer one validated candidate.* Quench boundaries that converged
   with a retained gradient become =CatalogCandidate= values through
   =lj_catalog_candidate= (examples/lj_cluster_search.rs:7144). The
   candidate is kept only when the gradient norm is at most 1e-5
   (examples/lj_cluster_search.rs:6861). One offer is made per
   checkpoint: the lowest-energy one, and only for a minimum not
   offered before. It is posted with
   =CooperativeRun::post_offer_candidate=
   (examples/lj_cluster_search.rs:5063-5079). The coordinator runs
   candidate validation (=CandidateValidator=, catalog.org "system
   signature and candidate validation") and, if it passes, attempts
   admission into =BasinCatalog= (catalog.org "active basin catalog").

4. *Report the current position.* Before any phase that can leave the
   checkpoint, it asks =DescriptorSpace::describe= for the descriptor
   of the current state (examples/lj_cluster_search.rs:5158). A failed
   describe returns at once. This runs on the checkpoints that reach
   it, including those that later reconfigure. It is not an identity
   claim: it reports wherever the chain stands, mid-hop or not. Only
   the offer in step 3 feeds the identity tier.

5. *A due probe can return before the barrier.* On a probe interval
   the checkpoint may poll =boundary_crossing= and return a
   =ProbeProposal= (examples/lj_cluster_search.rs:5185), or return from
   the fixed probe, before it reaches the population barrier. That
   return does not service the barrier on this visit.

6. *Service the population barrier.* The checkpoint answers the current
   synchronous population epoch: =join_population= when it should
   submit, =poll_population= when it is waiting, and
   =abstain_population= when it has nothing valid on file
   (examples/lj_cluster_search.rs:5429-5476). A checkpoint often finds
   the chain mid-hop with nothing yet valid. Silence there would leave
   the epoch waiting. Abstaining lets the epoch close without this
   replica (catalog.org "Feynman-Kac population epochs").

7. *Act on a ready population plan.* If the barrier just closed
   (=PopulationSynchronizationOutcome::Ready=), the replica reads its
   parent from the =PopulationEpochPlan=
   (examples/lj_cluster_search.rs:5477-5519). When =CATALOG_SHARED_BIAS=
   is =1=, the parent's coordinates are queued for this chain's bias.
   Unless =CATALOG_COOP_WELLS= is =0=, and the binary includes the
   =featomic= feature, the parent's SOAP cloud mean is folded into the
   shared packing archive (examples/lj_cluster_search.rs:5492). The
   example requires only =bank-rpc= (Cargo.toml:368), so the fold is
   absent until =featomic= is enabled as well. The occupancy rule
   (examples/lj_cluster_search.rs:5520-5620) keeps a replica on its own
   champion, may copy a deeper isomer of the same packing from another
   replica, and does not copy a parent from a different packing. A
   surplus body can leave through =featomic_hop::surplus_reseed=. The
   move returns through =population_reconfiguration=
   (examples/lj_cluster_search.rs:3714) as
   =CheckpointAction::BoundaryProposal=, and the checkpoint skips the
   ordinary policy decision below.

8. *Ask for a policy.* When no population reconfiguration fires,
   ~CATALOG_SYNC_POLICY=1~ waits and calls
   =CooperativeRun::policy_input_with_lambda=. Otherwise the request is
   asynchronous and calls =try_policy_input_with_lambda=, so a decision
   can act on a slice-old snapshot
   (examples/lj_cluster_search.rs:5913-5936). The descriptor is the one
   step 4 already computed. =decide= runs the pure
   =CatalogPolicy::decide= (catalog.org "catalog policy") against the
   coordinator's returned =CensusEvidence= and
   =ActiveCatalogRelation=.

9. *Act on the policy decision.* =ContinueLocal= does nothing further
   this checkpoint. =Exploit= may adopt the coordinator's incumbent
   (=try_sample_candidate=, action =catalog_incumbent=,
   examples/lj_cluster_search.rs:6289-6321). =Explore= asks for a
   descriptor hole (=descriptor_hole=, action =catalog_explore=,
   examples/lj_cluster_search.rs:6624-6663). =Leave= can reseed or move
   to another catalog entry (action =catalog_leave=).

10. *Record the slice trace.* Whatever happened, a =SliceTrace=
    (catalog.org "CooperativeRun composition layer") is recorded via
    =CooperativeRun::record_slice= before the checkpoint returns, so
    =CooperativeRun::json_lines= has one complete entry per checkpoint.

* Polish and offer

Separately from the checkpoint cadence, =Config.polish_records=
(src/methods/cluster_hopping/config.rs:1373) is a step count. It
lengthens the relaxation of a new record, and of a basin visit, not
of every hop. =run_capnp_catalog= sets it to =relax_steps=
(examples/lj_cluster_search.rs:4442), one full quench.
=Config::recommended= uses 1000 steps. With the count above zero, the
extra steps run when the record moves, and also when a basin visit
falls due after four times that many evaluations since the last polish
(src/methods/cluster_hopping.rs:11467). A target or a caller stop skips
both. A solo run leaves ~polish_records = 0~, which skips this path.
An offer in step 3 is kept only when the gradient norm is at most
1e-5 (examples/lj_cluster_search.rs:6861).

* Population epoch: reconfiguration

When enough replicas have joined a population epoch
(=SynchronousPopulation=, catalog.org "Feynman-Kac population epochs"),
the coordinator ranks the submitted =PopulationMember= entries
(=rank_population=), builds the bounded log-weight selection potential
from =SelectionCoefficients=, draws parents by systematic resampling at
a replayable per-epoch offset (=epoch_systematic_offset=), and caps
family sizes (=cap_families=). The resulting =PopulationEpochPlan= is
what step 7 above consumes. Genealogy diagnostics (Kish effective
sample size, unique parents, max and variance of family size) are
computed alongside the plan for later analysis, not consumed by the
replica itself.

* Reconfiguration and back to hopping

After a population reconfiguration or a boundary-crossing proposal is
accepted, the checkpoint returns control to
=run_with_bias_at_checkpoints=, which relaxes the new candidate state
through the ordinary quench and re-enters the hop loop. The chain's own
history (bias deposits, best-known state, tabu list) survives the
reconfiguration; only the live state changes. The next checkpoint
resumes at step 1.

* Termination and the run trace

The loop ends when the ledger reaches its target, the caller stop
is raised, or =remaining()= is zero
(src/methods/cluster_hopping.rs:6815). A finished checkpoint interval
is still delivered when nothing remains to charge. The same three
tests skip a side call (src/methods/cluster_hopping.rs:3746) and skip
record polish (src/methods/cluster_hopping.rs:5829). =Ledger::spent=
(src/methods/cluster_hopping.rs:1405) is the charged count. The example
writes =CooperativeRun::json_lines= to =CATALOG_TRACE= when that
variable names a path, and otherwise to stderr
(examples/lj_cluster_search.rs:6723-6740). The trace is the
newline-delimited event stream (catalog.org "CooperativeRun composition
layer") from which every mechanism's contribution to the run can be
replayed after the fact: which checkpoints offered a candidate, which
were rejected and why (=PolicyReason= codes), which population epochs
this replica joined versus abstained, and the charged-work ledger that
makes cross-replica comparisons auditable (catalog.org
"paired-seed evaluation methodology").

A separate observer may poll aggregate status through
=examples/catalog_status.rs=, which calls
=CatalogClient::observer_status= (src/catalog_rpc/client.rs:972).
That operation checks identity. The usage line requires
=SIGNATURE_HEX= with the campaign and the ensemble
(examples/catalog_status.rs:8). =system_identity_rejection= rejects a
mismatch on any of those three (src/catalog_rpc/server.rs:5766).
No replica slot or journal entry is required. The identity-free read
is =CatalogClient::observe= (src/catalog_rpc/client.rs:292), matching
=Coordinator.observe= (catalog.org "Cap'n Proto catalog protocol").

* Corrections and precise terminology

Three points in the narrative above use looser language than the code
supports. Stated precisely, with the file:line evidence.

** The five-fold typed design

"Five-fold" names the crate's own component algebra, not a separate
cooperative-layer invention: every chain runs the same typed
=Sampler<T>= point built from five interchangeable traits, the "IISE
manuscript" algebra each trait's own header comment cites directly:
=Cool : N -> R_>0= (src/cool.rs:1, non-increasing cooling schedule),
=Neigh : S -> 2^S= (src/neigh.rs:1, neighborhood relation, law L1:
symmetric), =Move : S x R_>0 -> Delta(S)= (src/movekernel.rs:1,
temperature-indexed proposal kernel, law L2: support contained in the
neighborhood), =Accept : R x R_>0 -> [0,1]= (src/accept.rs:1,
acceptance rule, law L3: downhill always accepted, law L4: acceptance
non-decreasing in temperature), plus the implicit objective (Obj).
~SaVariant::checked~ / ~checked_with_sweep~ (src/laws.rs:1-7) validate a
concrete tuple of components against all four composition laws, the
first three as Boolean witnesses and all four as executable proptest
sweeps. This is the README's "same five-component algebra (Obj / Cool
/ Neigh / Move / Accept)" (README.md:9), named precisely.

** Transport: Cap'n Proto RPC with a single-coordinator journal

There is no nng catalog transport and no raft-style or other
distributed consensus for the catalog: one coordinator process owns
the journal. What is actually there:

- Transport: two-party Cap'n Proto RPC on TCP. =Catalog.capnp=
  defines =Coordinator=, =Session=, and =Subscriber=. A replica
  calls =attach= with its identity and a subscriber capability, then
  =Session.call= carries the existing =CatalogRequest= /
  =CatalogReply= payload so journal identity and every operation
  handler stay unchanged. =Coordinator.observe= needs no identity.
- Coordination: =CatalogServer::start= binds one socket and runs a
  single =RpcSystem= accept loop on a dedicated thread with a tokio
  =LocalSet= that owns coordinator state. Candidate validation that
  does not depend on that state runs on a rayon pool and is awaited
  before the request is applied. The coordinator pushes
  =CoordinatorEvent= values to every attached subscriber when an
  epoch closes, when the roster changes, and when a replica retires.
- Durability: a single append-only request journal
  (~append_journal~ / ~replay_journal~), replayed at startup and keyed
  by =(replica, event_sequence)= so a restarted coordinator recovers
  the same state a live one would have, and a resent request after a
  dropped reply is a no-op rather than a double-charge. This is crash
  recovery for one process, not agreement among several.

Anywhere the narrative above says "the coordinator" it means this: one
process, one LocalSet, one journal. A second coordinator process
pointed at the same journal path would corrupt it; nothing in this
crate arbitrates between two.

** neus_bridge: the bridge layer between chains holding different minima

[[file:catalog.org::*Nonequilibrium-umbrella bridge between two minima (=neus_bridge=)][neus_bridge]]
supplies the machinery of the bridge layer: an image string between
two validated catalog basins, Voronoi-region membership, and
flux-balance weight transfer producing a committor surrogate along
the channel. The wiring closes the loop the other cooperative
mechanisms open. The
[[file:catalog.org::*Spectral referee over the explored landscape (=landscape_graph=)][spectral referee]]
names the seam. Nothing in the coordinator inserts a bridge, so
the bridge map stays empty. The assignment poll
(src/catalog_rpc/server.rs:1659) and the crossing report
(src/catalog_rpc/server.rs:1705) are still served, and a poll of an
empty map returns no bridge. When =CATALOG_BRIDGE= is =1=
(examples/lj_cluster_search.rs:4346), the run loop jumps to a stored
entry state when one exists and reports region changes of the live
descriptor as crossings. Confinement is soft: crossings are recorded
rather than moves rejected, so no chain's acceptance rule changes.
The variable turns that flag on only for the value 1 (src/env.rs:23).
=CATALOG_SHARED_BIAS= uses the same test.
