* eOn Potentials Over rgpot

The **eOn ↔ rgpot** integration gives eOn access to rgpot's quantum-chemistry
backends (**NWChem** via =nwchemc=, **CPMD** e.g. BLYP via =cpmdc=) through two
independent roles:

- **In-process (shipped in eOn):** eOn's =RgpotPot= (=-Dwith_rgpot=true=) links
rgpot's =NWChemPot= / =CPMDPot= frontends as a Meson subproject and
=dlopen=s the engine libraries directly. No sockets, no potserv. Configured through the eOn =[RgpotPot]=
INI section (=backend=, =basis=, =theory=,
=scf_type=, =functional=, =charge=, =multiplicity=, =engine_library=, ...).
- **Out-of-process RPC (this repo):** =potserv <port> NWChem|CPMD= serves the
Cap'n Proto =Potential= interface for any client; eOn can also act as an RPC
*server* via =eonclient --serve= (=-Dwith_serve=true=).

Engine builds live in =nwchemc= / =cpmdc=; rgpot frontends =dlopen= them at
runtime in both roles.

Why the integration is shaped this way is in
[[file:../explanation/rpc-model.org][The RPC Model]], under eOn over rgpot.

* Operator Cheatsheet (rgpot side)

=potserv <port> <PotentialType>= selects the backend.
Every build accepts =LJ=, =LJCluster=, =Morse=, =ZBL=, =Composite=, =D2=,
=NWChem=, =NWChem:basis[:theory[:xc]]= and =CPMD=.
A Fortran build also accepts =CuH2=.
The remaining names are present only when that backend was compiled in:
=IPI:unix:<path>= and =IPI:tcp:<host>:<port>=; =XTB= (GFN2-xTB), =GFNFF=,
=GFN0xTB= and =GFN1xTB=; =TBLite= (the same backend as =TBLiteGFN2=),
=TBLiteGFN1= and =TBLiteIPEA1=; =D3= and =D4=;
=Metatomic:<model_path>[:<device>]=; =Uma:<model_path>= and
=Uma:<model_path>:<task>=, with a task of =omol=, =omat=, =oc20=, =oc22=,
=oc25=, =odac= or =omc=; =Skala= and =Skala:<basis>=; and =CP2K=.
A missing type prints that list for the binary that is running.
The =configure= arms are a separate list, on
[[file:../reference/potential_config.org][PotentialConfig arms]].
The fake engines and =potserv= are built with
=-Dwith_rpc=true -Dwith_tests=true=.
=tests/test_rpc_e2e_c_abi.py= needs =RGPOT_POTSERV= and one engine variable per
backend, and fails when one is missing.

#+attr_rgpot: syntax
#+begin_src bash
# Real engines (built in OmniPotentRPC/nwchemc and OmniPotentRPC/cpmdc)
NWCHEMC_LIBRARY=/path/to/libnwchemc.so ./bbdir/CppCore/potserv 12345 NWChem
CPMDC_LIBRARY=/path/to/libcpmdc.so   ./bbdir/CppCore/potserv 12346 CPMD

# Fake engines (meson -Dwith_rpc=true -Dwith_tests=true)
export RGPOT_POTSERV=./bbdir/CppCore/potserv
export NWCHEMC_LIBRARY=./bbdir/CppCore/libnwchemc_fake_engine.so
export RGPOT_CPMD_ENGINE=./bbdir/CppCore/libcpmdc_fake_engine.so
pixi run -e rpctest -- python tests/test_rpc_e2e_c_abi.py
#+end_src

See =CppCore/rgpot/NWChemPot/README.md=, =CppCore/rgpot/CPMDPot/README.md=, and
