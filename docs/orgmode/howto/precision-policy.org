* Three Channels

Any =Accept= that claims to implement the exact Metropolis (or =Tsallis=) rule under floating-point must use one of the three documented channels:

- C1 (compensated summation in the log-acceptance ratio)
- C2 (log-domain formulation that never forms the ratio explicitly)
- C3 (online-suffix-averaging / OSA guard against cancellation when comparing the incumbent)

The crate builds with the safe default.
The experiments under =experiments/exp1_underflow.py= ...
=exp4_compensated.py= demonstrate the failure modes each channel closes (underflow in the ratio, cancellation when the incumbent is already the best-so-far, etc.).

See the IISE manuscript section on finite-precision effects and the SymPy witnesses in =proofs/= for the exact identities that the three channels preserve.

In user code you do not choose the channel; you choose an =Accept= implementation that advertises the contract.
All presets and advanced drivers in the current surface use a channel that passes the laws checker.

* Deterministic cluster performance

Cluster hot paths keep the arithmetic and random-number order fixed.
Pair energies and gradients are reduced in the same serial pair order.
A descriptor is reused only when its key is a pure function of the coordinates.
Stateful online descriptors retain every call in its original order.
The per-cluster reductions do not use Rayon because another reduction tree changes floating-point bits and can change a seeded trajectory.
Independent seeds may still run in parallel.

Run the focused Criterion suite with:

#+begin_src sh
cargo bench --bench globalopt_hotpaths
#+end_src

The suite covers Lennard-Jones 75- and 98-point gradients.
It also covers sorted pair descriptors, open-boundary neighbour construction, and a screened local minimisation.
The rigid benchmarks cover ten-water TIP4P energy, its gradient, and rigid-body descriptors.
For trajectory checks, run the same release executable twice with the same seed and compare the complete output with =cmp= or =sha256sum=.
