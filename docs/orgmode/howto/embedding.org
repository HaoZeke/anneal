* Embedding as a Subproject

This page covers how to embed rgpot into another C/C++ project using meson or
cmake as a subproject dependency.

** Meson

Add a
=subprojects/rgpot.wrap= file or vendor the source directly into =subprojects/rgpot/=.

*** Full library build (server + potentials)

Use this when your project hosts an RPC server with rgpot's built-in potentials:

#+attr_rgpot: fragment
#+begin_src meson
rgpot_proj = subproject('rgpot',
    default_options: ['with_rpc=true', 'with_tests=false'])
rgpot_dep = rgpot_proj.get_variable('rgpot_dep')
#+end_src

*** Linking without OpenMP

=rgpot_dep= passes rgpot's OpenMP dependency on, so the consumer compiles and
links with =-fopenmp=.
A consumer that does not use OpenMP itself takes =rgpot_dep_no_openmp=, which
has the same headers, defines and libraries without the OpenMP flag:

#+attr_rgpot: fragment
#+begin_src meson
rgpot_proj = subproject('rgpot', default_options: ['with_tests=false'])
rgpot_dep_no_openmp = rgpot_proj.get_variable('rgpot_dep_no_openmp')
#+end_src

librgpot is still built with OpenMP, and its potentials open their thread teams
as before, under =OMP_NUM_THREADS=.
A shared librgpot records the OpenMP runtime as =NEEDED=.
A static librgpot (=default_library=static=) links the runtime library by name
(=libgomp= for GCC, =libomp= for Clang), so the consumer's link line names that
library rather than =-fopenmp=.
With a compiler whose runtime is not found by name, a static build keeps the
flag on the link line, and configure says so.
The templates in =rgpot/Slices.hpp= run serially in a translation unit compiled
without =_OPENMP=; their instantiations in librgpot do not change.
A client-only build (=with_rpc_client_only=) defines =rgpot_dep_no_openmp= as
=rgpot_dep=, which carries no OpenMP flag there.

For a shared librgpot, the =Cflags= and =Libs= of the installed =rgpot.pc= carry
no OpenMP flag, and =Libs.private=, which =pkg-config --static= reads, keeps it.
A static librgpot has meson write its dependencies into =Cflags= and =Libs=:
=Libs= names the runtime library rather than =-fopenmp=, and =Cflags= keeps the
OpenMP compile flag.

*** RPC schema only (client mode)

Use this when your project only needs to /call/ a remote potential server, or
when you want to avoid namespace collisions with your own types (see
[[file:integration.org][integration guide]]):

#+attr_rgpot: fragment
#+begin_src meson
rgpot_proj = subproject('rgpot',
    default_options: ['with_rpc_client_only=true', 'pure_lib=true'])
ptlrpc_dep = rgpot_proj.get_variable('ptlrpc_dep')
#+end_src

The =ptlrpc_dep= provides only the Cap'n Proto schema and generated code,
without pulling in =Potential.hpp= or the existing C++ potentials.
It links =ptlrpc=, a static convenience archive
(=CppCore/rgpot/rpc/meson.build=).
A client-only build does not build =librgpot=.
A build without =with_rpc_client_only= links the same archive whole into
=librgpot=, so a consumer that resolves rgpot through =pkg-config= has no
separate =libptlrpc= to find at run time.

*** Feature-gated potentials (Meson)

Optional backends are off by default so the core library stays lightweight.
Enable only what the host project needs:

| Meson option | pixi env | Backend |
|--------------+----------+---------|
| =-Dwith_xtb=true= | =xtbbld= / =tbbld= | =XTBPot= (GFNFF, GFN0/1/2-xTB) |
| =-Dwith_tblite=true= | =tblitebld= / =tbbld= | =TBLitePot= (GFN1, GFN2, IPEA1) |
| =-Dwith_dftd3=true= | =dftd3= / =dftd= | =D3Pot= in-process Potential summand (DFT-D3 BJ/zero, explicit ATM; =PotentialConfig.d3= is not applied and every =potserv= backend refuses it; goldens =meson test --suite dftd=) |
| =-Dwith_dftd4=true= | =dftd4= / =dftd= | =D4Pot= in-process Potential summand (DFT-D4 functional/charge, explicit ATM; =PotentialConfig.d4= configures the =D4= backend and a =d4= composite term; goldens =meson test --suite dftd=) |
| =-Dwith_expr=true= | none (vendored OpenMM Lepton; no pixi muparser) | =ExprPot= named-child PES algebra (=potserv= refuses =PotentialConfig.expr=) |
| =-Dwith_metatomic=true= | =metatomicbld= (linux-64) | =MetatomicPot= (TorchScript models) |

=NWChemPot= is a pure consumer: the frontend =dlopen=s =libnwchemc.so= from
[[https://github.com/OmniPotentRPC/nwchemc][nwchemc]] (stable
=nwchemc_*= C symbols). rgpot builds no in-process NWChem embed of its own and has no =-Dwith_nwchem=
option.
No =nwchem= CLI/subprocess path.
Build =libnwchemc.so= from the =nwchemc= project, then set
=NWCHEMC_LIBRARY=, =RGPOT_NWCHEMC_ENGINE= or =RGPOT_NWCHEM_ENGINE=.
See =CppCore/rgpot/NWChemPot/README.md=.

=CPMDPot= follows the same split-engine pattern: the frontend
=dlopen=s =libcpmdc.so= from [[https://github.com/OmniPotentRPC/cpmdc] [cpmdc]].
Both frontends use the Cap'n Proto parameter structs, so they are compiled only
when =with_rpc= or =with_rpc_client_only= is on (CMake: =RGPOT_WITH_RPC=).
The engine is documented at [[https://cpmdc.rgoswami.me][cpmdc.rgoswami.me]].
rgpot builds no in-process OpenCPMD embed of its own and has no =-Dwith_cpmd=
option.
Build =libcpmdc.so= from the =cpmdc= project, then set
=CPMDC_LIBRARY=, =RGPOT_CPMDC_ENGINE=, or =RGPOT_CPMD_ENGINE=.
See =CppCore/rgpot/CPMDPot/README.md=.

Example -- embed with metatomic support:

#+attr_rgpot: fragment
#+begin_src meson
rgpot_proj = subproject('rgpot',
    default_options: [
      'with_rpc=true',
      'with_metatomic=true',
      'with_tests=false',
    ])
rgpot_dep = rgpot_proj.get_variable('rgpot_dep')
#+end_src

The metatomic path needs PyTorch, =metatensor=,
=metatensor_torch= and =metatomic_torch= installed for the =python3= that Meson
finds.
Meson does not use the Torch CMake package.
It locates =torch/version.py= through =RGPOT_TORCH_ROOT= or =sys.path= without
importing torch.
It then passes =-L=, =-ltorch=, =-ltorch_cpu= and =-lc10= (with
=-Wl,-rpath-link= on GNU ld).
The metatensor and metatomic headers and libraries come from the =purelib=
directory of that Python.
=vesin= comes from the top-level =vesin= dependency, with the copy in
=third_party/vesin= as the fallback.
Torch links only into the =metatomic_engine= plugin, not into =librgpot=.

For the *pip* wheel (nanobind abi3 + multi-ABI =dlopen= engines, torch *2.7+*),
see:

#+begin_export rst
:doc:`pip-python`
#+end_export

instead of embedding as a subproject.

** CMake

rgpot also provides a CMake build.
To use it as a subdirectory:

#+attr_rgpot: fragment
#+begin_src cmake
set(RGPOT_WITH_CACHE OFF CACHE BOOL "" FORCE)
add_subdirectory(external/rgpot)
target_link_libraries(my_target PRIVATE rgpot::rgpot)
#+end_src

=rgpot::rgpot= keeps OpenMP private: its consumers compile without the OpenMP
flag.
A static =rgpot= links them with the OpenMP runtime library that =FindOpenMP=
found, not with =-fopenmp=, and the installed =rgpotConfig.cmake= finds OpenMP
for that.

=rgpot::rgpot= exists only when =RGPOT_RPC_CLIENT_ONLY= is =OFF=.
A client-only build defines the =ptlrpc= and =rgpot_client_bridge= targets
instead.

*** Build options

| Option | Default | Description |
|--------+---------+-------------|
| =RGPOT_BUILD_TESTS= | =ON= when rgpot is the top-level project, else =OFF= | Build the test suite |
| =RGPOT_BUILD_EXAMPLES= | =ON= when rgpot is the top-level project, else =OFF= | Build example programs |
| =RGPOT_RPC_CLIENT_ONLY= | =OFF= | Build only the RPC client (schema library and client bridge) |
| =RGPOT_WITH_CACHE= | =ON= | Build =PotentialCache= against RocksDB |

=RGPOT_WITH_CACHE= defaults to =ON= and =find_package(RocksDB REQUIRED)= then
fails without RocksDB.
The snippet above turns it off before =add_subdirectory=.
Meson's =with_cache= defaults to =false=.
=RGPOT_RPC_CLIENT_ONLY= forces the cache off.
See the build options reference for every option:

#+begin_export rst
:doc:`../reference/build_options`
#+end_export

#+attr_rgpot: syntax
#+begin_src bash
cmake -B build -DRGPOT_BUILD_TESTS=ON -DRGPOT_BUILD_EXAMPLES=ON
cmake --build build
ctest --test-dir build
#+end_src

** Windows (MSVC)

rgpot builds on Windows with MSVC 2022.
Install Cap'n Proto via conda-forge or vcpkg, then use the standard meson or
cmake workflow.
CI builds with Meson on =windows-2022= with the Fortran potentials enabled.
For those it sets =AR=lib= and passes
=--native-file ci/gha/machines/win-flang-msvc.ini=, so MSVC =lib.exe= archives
the Flang objects.

The Meson build handles the following itself:

- =CppCore/rgpot/rpc/capnp_compile.py= runs =capnp compile -oc++= instead of
  =capnpc=
- It renames the generated
  =.c++= file to =.cpp= (MSVC does not recognize the =.c++= extension)
- =ws2_32= is linked for Cap'n Proto's async networking layer
- =with_ipi= (=auto=) stays off, since the i-PI potential needs POSIX sockets
