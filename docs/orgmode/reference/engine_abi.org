* Engine plugin ABI

=CppCore/rgpot/engine_c_abi.h= is the function table a host uses to drive an
engine shared library without linking the library's tensor runtime or its
backend.
Backend selection is which library the host opens with =dlopen=, and the
configuration is a Cap'n Proto flat-array message whose root is the engine's
params struct.
Units are Angstrom, eV and eV/Angstrom, and a box is nine doubles in row-major
order.
A call returns 0 on success, a positive value when the evaluation failed at this
input and the caller may back off, and a negative value when the instance is
unusable.
The engines in this repository return 1 for an invalid argument, 2 for a failed
evaluation or setting (the reason is in
=rgpot_engine_last_error=), 3 when the backend does not support the operation, and for =rgpot_engine_force=
the transform's own nonzero code.

** One table for every backend

=CppCore/rgpot/engine/EngineTable.cc= exports every =rgpot_engine_*= symbol for
any =PotentialBase=.
A backend library adds a small file that builds its potential from the params
message and defines two functions, =rgpot::engine::create= and
=rgpot::engine::backend_name=; the table does argument validation, the
coordinate transform, batching, error text, the thread-safety policy, the
identity queries and the Python GIL release.

| library | root message | selects |
|---------+--------------+---------|
| =libuma_engine= | =UmaParams= | the UMA package |
| =libmetatomic_engine= | =MetatomicParams= | the metatomic model |
| =libxtb_engine= | =BuiltinParams= | name =xtb=, GFN2-xTB defaults |
| =libclassical_engine= | =BuiltinParams= | =lj=, =ljcluster=, =morse=, =zbl= and, with the Fortran kernels, =sw=, =edip=, =lenosky=, =tersoff=, =eamal=, =fehe=, =cuh2=, =waterh=, all with default parameters |
| =libmopac_engine= | =BuiltinParams= | name =mopac=; =library= is the path of =libmopacc= |
| =libnwchem_engine= | =NWChemParams= | NWChem through =libnwchemc= |
| =libskala_engine= | =NWChemParams= | Skala XC on NWChem; reads =basis=, =charge=, =multiplicity=, =enginePath= and =nwchemRoot= |

The Metatomic and XTB engines keep their own tables
(=rgpot_mta_*=, =rgpot_xtb_*=) beside the generic one.
NWChem and CPMD also keep the prefix-parameterized profile ABI that =NWChemPot=
and =CPMDPot= load, and MOPAC keeps =mopac_c_abi.h=.
The plugin interface in =rgpot/plugin.h= is a separate family.
The remaining backends (tblite, dftd3, dftd4, ExprPot, XcKernel, CPMD, CP2K)
have no engine library.

** CP2K shim

=CP2KPot= drives CP2K through
=libcp2kc_rgpot=, a shim over libcp2k declared in =CppCore/rgpot/CP2KPot/cp2kc_abi.h=
(=CP2KC_ABI_VERSION= 1).
The shim is the only target that links libcp2k and MPI; =CP2KPot= opens it with
=dlopen=, so =librgpot= gains neither dependency.
Meson builds it with
=-Dwith_cp2k=enabled= from the =libcp2k= pkg-config module (CMake: =-DRGPOT_WITH_CP2K=ON=).
Without it =librgpot= contains no CP2K code, =potserv CP2K= exits with an error
naming the option, and every other backend refuses the =cp2k= arm in
=configure()=.
=CP2KPot= searches =CP2KParams.enginePath=, then
=CP2KC_LIBRARY=, then =RGPOT_CP2K_ENGINE=, then =libcp2kc_rgpot.so= on the
loader path.

| symbol | purpose |
|--------+---------|
| =cp2kc_abi_version=, =cp2kc_version=, =cp2kc_available= | identity |
| =cp2kc_adopt_calculator_comm= | borrow the calculator's =MPI_Comm= |
| =cp2kc_session_create= | write the deck to =dir/input.inp=, initialise libcp2k once |
| =cp2kc_session_select_orbitals= | name the key whose force environment the next call uses |
| =cp2kc_session_calculate= | positions and cell in Bohr in, Hartree and Hartree/Bohr forces out |
| =cp2kc_session_destroy= | destroy the session's force environments |

The shim speaks CP2K's atomic units and takes no Cap'n Proto.
=CP2KPot= renders the deck from =CP2KParams= and the first geometry, multiplies
positions and cell rows by =ANGSTROM_TO_BOHR=, and returns the energy times
=HARTREE_TO_EV= and the forces times =HARTREE_BOHR_TO_EV_ANGSTROM=. libcp2k
returns forces, so no sign changes.
The cell rows are the cell vectors: =cp2k_set_cell= reshapes the nine values
column-wise into CP2K's =hmat=, whose columns are the vectors.

=cp2kc_session_calculate= returns 0 on success, 1 for a bad argument (including
an atom count that differs from the deck), 2 when the SCF did not converge, and
a negative value on a fatal error.
The rendered deck sets =IGNORE_CONVERGENCE_FAILURE=, so CP2K warns instead of
calling =MPI_ABORT=.
After each evaluation the first rank of the calculator reads the new part of
=cp2k.out= for =SCF run NOT converged= and broadcasts the result, so every rank
returns 2 for the same call.
=CP2KPot= turns that code into =rgpot::CP2KScfError= on every rank without the
error exchange, and an engine-table host maps it to its recoverable code 2.
Any other failure takes the abort path described in [[file:mpi.org][MPI]].
libcp2k has no stress getter, so =has_stress= is 0.

** Symbols

Required:
=rgpot_engine_abi_version=, =rgpot_engine_available=, =rgpot_engine_create=, =rgpot_engine_destroy=, =rgpot_engine_force=.

Optional, probed with =dlsym=:

| symbol | purpose |
|--------+---------|
| =rgpot_engine_force_batch= | one composition, system stride =3*nAtoms= and 9 |
| =rgpot_engine_abi_stamp=, =rgpot_engine_abi_compatible= | major, minor and layout revision |
| =rgpot_engine_name=, =rgpot_engine_version= | backend name and =<name>/<rgpot version>= |
| =rgpot_engine_model_digest= | SHA-256 of the loaded model file as 64 hexadecimal digits; 0 when the backend has no model file |
| =rgpot_engine_caps= | the engine-side =PotCaps=: reentrancy, per-image instances, batching, periodicity, stress |
| =rgpot_engine_last_error= | message of the last failed call on an instance |
| =rgpot_engine_set_num_threads= | intra-op and inter-op threads of the tensor runtime |
| =rgpot_engine_set_charge_spin= | charge and spin multiplicity of the next calls |
| =rgpot_engine_model_state=, =rgpot_engine_set_callbacks=, =rgpot_engine_hint= | learning engines |
| =rgpot_engine_neighbor_options= | neighbor lists the host must provision |

Every engine built on the table exports all of them down to
=rgpot_engine_set_charge_spin=.
=rgpot_engine_set_num_threads= returns 3 for a backend without a tensor runtime,
and =rgpot_engine_set_charge_spin= returns 3 for a backend without a charge or
spin and for a value the backend cannot take.

** Tensor runtime parameters

=UmaParams= and =MetatomicParams= carry =intraopThreads= and =interopThreads=
(default 1; a value below 1 leaves the runtime alone), applied once when the
engine creates the model.
=UmaParams.deterministicAlgorithms= requests deterministic torch algorithms.
=MetatomicParams.torchDeterminism= (=fast= or =deterministic=) is the same
request for that arm, with the attention-backend and TF32 restrictions of
rgpot's =TorchDeterminismPolicy=, and =nSymmetryRotations=, =randomRotation= and
=so3ProbeScatter= mirror =MetatomicConfig=.
The inter-op count can be set once per process before the runtime starts
parallel work; asking for the value already in force is accepted, and another
value afterwards fails =create= (or =rgpot_engine_set_num_threads=) with the
reason.
The thread counts act on the process's libtorch, so two engines in one process
share them.

** Charge and spin

=rgpot_engine_set_charge_spin= sets the total charge and the spin multiplicity
of the next calls on a handle, and a multiplicity below 1 returns 1.
A value the backend cannot take returns 3, keeps the values in force and leaves
the reason in =rgpot_engine_last_error=.
No engine returns 0 for a value its model does not receive.

| library | charge and multiplicity |
|---------+-------------------------|
| =libuma_engine= | graph inputs of every call; =UmaParams.charge= and =spin= at create |
| =libmetatomic_engine= | system data the model declares; =MetatomicParams.charge= and =spin= at create |
| =libskala_engine= | the NWChem input of the next call; =NWChemParams.charge= and =multiplicity= at create |
| =libclassical_engine=, =libmopac_engine=, =libnwchem_engine=, =libxtb_engine= | none, so 3 for any value |

A UMA package records the charge and spin it was exported for, and the next
force call reports a mismatch.
A Metatomic model reads the charge as =rgpot::charge= and the multiplicity as
=rgpot::spin_multiplicity= or =rgpot::spin=.
Each system carries the names the model declares in =requested_inputs=.
A model that declares none of them gets 3 from =rgpot_engine_set_charge_spin=.
A value the model does not read must stay at its default, charge 0 or
multiplicity 1.
=rgpot_engine_set_charge_spin= returns 3 for another, and =create= fails for one
in =MetatomicParams=.
=MetatomicParams.attachSystemExtras= attaches all three names and accepts any
value, for a model that reads them without declaring them.
It needs =checkConsistency= off, because metatomic then rejects data the model
does not declare.
[[file:../howto/engine-metatomic.org][Metatomic and the engine ABI]] shows the
declaration.

** UMA unpack cache

=UmaParams.cacheDir= (=UmaConfig::cache_dir= for a directly compiled =UmaPot=)
names the root of the persistent cache that the =.pt2= is unpacked into.
When it is empty the root is =$RGPOT_CACHE_DIR=, then =$XDG_CACHE_HOME/rgpot=
(absolute values only), then =.rgpot-cache= in the working directory. torch's
=AOTIModelPackageLoader= is not used, because it unpacks into a new directory
under the system temporary directory and leaves it behind when the process dies.

| Path under the root                         | Contents                                             |
|---------------------------------------------+------------------------------------------------------|
| =aoti/<sha256>.model/=                      | the package's =data/aotinductor/model= files and constants, as torch lays them out |
| =aoti/<sha256>.model/rgpot-unpack.manifest= | package digest, model name, and the size of every unpacked file |
| =aoti/.<sha256>.model.tmp-*=                | an unpack in progress                                |

=<sha256>= is the digest of the =.pt2= bytes, so two models never share a
directory and a rewritten package gets a new one.
An unpack is written into a private =.tmp-= sibling and renamed into place once
its manifest is complete.
Processes and threads that load the same package at once each build a sibling,
one rename wins, and the others use the winner's directory.
A directory whose manifest is missing or whose files have the wrong size is
replaced.
Shared libraries lose the executable-stack flag (=PT_GNU_STACK= =PF_X=) on the
way, for loaders that refuse an executable stack.
A =.tmp-= sibling older than an hour, left by a process that died, is removed
the next time that package is loaded.

** UMA checkpoint provenance

=rgpot_engine_model_digest= of =libuma_engine= is the SHA-256 of the =.pt2=.
The digest of the weights inside it is package metadata, written by
=scripts/export_uma_aoti.py=:

| Key                      | Value                                                          |
|--------------------------+----------------------------------------------------------------|
| =checkpoint_source=      | =cli=, =env= or =hf=: where the exporter took the checkpoint from |
| =checkpoint_path=        | the local checkpoint file (=cli= and =env=)                    |
| =checkpoint_hf_repo=     | Hugging Face repository (=hf=)                                 |
| =checkpoint_hf_filename= | file inside that repository (=hf=)                             |
| =checkpoint_hf_revision= | commit the file was served from (=hf=)                         |
| =checkpoint_sha256=      | SHA-256 of the checkpoint file, 64 lowercase hexadecimal digits |

=UmaPot::checkpointProvenance()= returns them as a =UmaCheckpointProvenance=,
whose fields are =std::optional= and unset for packages exported before the keys
existed.
The engine prints =UmaPot: checkpoint_sha256== on stderr when it loads the
package (=unset= for those packages); the table exports no symbol for the keys.
A malformed =checkpoint_sha256=, =checkpoint_hf_revision= or =checkpoint_source=
fails the load.

** Thread safety of a handle

Any thread may call =rgpot_engine_force= and =rgpot_engine_force_batch= on any
handle.
What happens inside follows the backend's =rgpot_engine_caps().reentrancy=:

- 0, shared instance: calls run concurrently on one handle (UMA, Metatomic and
  the classical shared-state-free potentials).
- 1, per instance: the engine admits one call at a time per handle, so a handle
  is safe from any thread and calls on it are serialized; handles do not wait
  for each other.
  A host that wants parallelism creates one handle per worker (XTB and the
  Fortran potentials).
- 2, process serial: the engine admits one call at a time in the process across
  all handles of the library (MOPAC, NWChem, Skala).

=rgpot_engine_set_num_threads=, =rgpot_engine_set_charge_spin=,
=rgpot_engine_set_callbacks=, =rgpot_engine_hint= and =rgpot_engine_destroy=
must not run concurrently with a call on the same handle.
=rgpot_engine_last_error= and =rgpot_engine_model_digest= may run at any time.
=EngineAdapterTest= checks each policy with a stand-in backend that records how
many calls are inside it at once; =EngineTableTest= and =UmaEngineTest= run
eight and four threads on one handle.

** Version scheme

=RGPOT_ENGINE_ABI_VERSION= is the major and a host compares it for equality.
=RGPOT_ENGINE_ABI_MINOR= increments for an addition that leaves every existing
call valid: a new optional symbol, or a new field at the end of a size-prefixed
structure.
=RGPOT_ENGINE_ABI_LAYOUT_REVISION= increments when an existing structure changes
size or field order.
A host built against minor N runs against an engine of the same major and layout
revision whose minor is at least N. An engine without =rgpot_engine_abi_stamp=
is minor 0, layout 1.
Minor 1 added the stamp, =caps=,
=last_error=, =set_num_threads= and =set_charge_spin=; minor 2 added =name=, =version= and =model_digest=
and the generic table for every backend.
Structures that grow (=RgpotEngineCaps=) begin with a =size= field, so an older
host receives the bytes it announced room for.
The version covers the table and its conventions; it does not cover the Cap'n
Proto params schema (versioned by the =potentials-schema= pin), the tensor
runtime the engine links, or the model.

To open, build and test an engine, see
[[file:../howto/engine-plugins.org][Open, build and test engine plugins]].
