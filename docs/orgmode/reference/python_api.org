* Python API

The extension module is =rgpot._core=.
Stubs live in =rgpot/_core.pyi= and the package ships =py.typed=.
Wrong dtype or order on a float64 argument raises =TypeError=.
A wrong shape raises =ValueError= naming the argument and both shapes.
A non-finite energy raises =rgpot.NumericalError=.

** Calculators

| Symbol                  | Role                                      |
|-------------------------+-------------------------------------------|
| =rgpot.ase.RgpotCalculator= | In-process ASE calculator            |
| =rgpot.ase.RgpotRpcCalculator= | Cap'n Proto ASE calculator      |
| =rgpot.ase.AnnealRunner= | Portfolio relaxation, not an ASE optimizer |
| =rgpot.ase.AnnealOptimizer= | Deprecated alias of =AnnealRunner=   |

=RgpotCalculator.calculate_many(frames)= returns one dict per frame.
=threads= selects the worker count; 0 uses the hardware concurrency.
Results for energy and forces match one call per frame, bit for bit.
The worker count is not part of the result.

See the [[file:../howto/ase.org][ASE how-to]] and the
[[file:../explanation/thread-safety.org][thread-safety]] page.

** Hessian-vector products

Every potential object has
=hvp(positions, atom_types, box, direction, step=0.0, scheme="auto")=, which
returns =H v= with the shape of =positions=.
=scheme= is ="forward"=, ="central"=, ="analytic"= or ="auto"=, and =step= 0 is
1e-3 Angstrom.
="forward"= reuses the forces of the last geometry the object evaluated, so a
Lanczos loop of =k= products at one geometry costs =k + 1= force calls, at
first order in =step=.
="central"= costs two calls a product, at second order.
="auto"= is ="analytic"= when =has_analytic_hvp()= is true, as for =MorsePot=,
and ="forward"= otherwise.

#+begin_src python
pot = rgpot.MorsePot()
energy, forces, _ = pot.hvp_centre(positions, types, box)
for v in directions:
    hv = pot.hvp(positions, types, box, v, scheme="forward")
pot.hvp_counts()  # {"products": k, "force_calls": k + 1, ...}
#+end_src

=hvp_centre= returns the energy and forces of that centre.
The centre is keyed on the bits of the positions, types and cell; another
geometry is a new centre, and =invalidate_hvp()= drops it.
=hvp_counts()= and =reset_hvp_counts()= read and zero the call counters.
The products follow =rgpot_potential_hvp=; see the
[[file:c_abi.org][C ABI reference]] for the error terms of each scheme.

** Engine constructors

=rgpot.rgpot_lammps_potential=, =rgpot.rgpot_gromacs_potential= and
=rgpot.rgpot_openmm_potential= return a shifted 12-6 potential.
Positions are Angstrom and the energy is eV.
The LAMMPS constructor dlopens the engine plugin.
GROMACS and OpenMM store kJ/mol and nanometres once;
=native_u0=, =native_cutoff= and =native_psi= read those stored values.
The dimer at 1.5 Angstrom with =u0= 1, cutoff 8 and =psi= 1 is -0.3203213355 eV.

** XcKernel

=XcKernel.contract= takes =chi=, an optional =dchi= (default =None=), and a
required =scal= dict.
The stub writes =scal= as =None= so =dchi= can be omitted.
Passing =None= for =scal= raises =TypeError=.
=k.contract(chi, None, scal)= and =k.contract(chi, scal=scal)= both leave =dchi=
null.
=lapl_chi= and =hess_chi= default to =None=.
