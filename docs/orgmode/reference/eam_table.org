* Tabulated EAM and Finnis-Sinclair potentials

=EAMTablePot= reads an embedded atom method (EAM) potential from a DYNAMO table
and evaluates

#+attr_rgpot: skip the energy formula, not code
#+begin_example
E = sum_i F_a(rho_i) + sum_{i<j} phi_ab(r_ij)
rho_i = sum_{j != i} rho_ab(r_ij)
#+end_example

where a is the element of atom i, b is the element of atom j, and =rho_ab= is
the density a b neighbor puts at an a site.
The three layouts are those of the =pair_eam= page of the Large-scale
Atomic/Molecular Massively Parallel Simulator (LAMMPS),
https://docs.lammps.org/pair_eam.html.

| =EAMTableFormat= | LAMMPS style      | Suffix        | Arrays                                 |
|------------------+-------------------+---------------+----------------------------------------|
| =Funcfl=         | =eam=             | =.eam=        | F(rho), Z(r), rho(r), one element      |
| =Setfl=          | =eam/alloy=       | =.eam.alloy=  | F_a(rho), rho_b(r), r phi_ab(r)        |
| =FinnisSinclair= | =eam/fs=          | =.eam.fs=     | F_a(rho), rho_ab(r), r phi_ab(r)       |

A =Setfl= density depends only on the neighbor, so ~rho_ab = rho_b~.
The =FinnisSinclair= layout carries a density for each ordered pair of elements.
It is the form of Finnis and Sinclair, Philosophical Magazine A 50, 45 (1984).
Section b of an =.eam.fs= file lists F_b and then ~rho_1b~ to ~rho_Nb~, the
density b puts at a site of each element in turn.

The potential is opt-in.
Meson builds it with =-Dwith_eam_table=true= and CMake with
=-DRGPOT_WITH_EAM_TABLE=ON=.
Both define =RGPOT_HAS_EAM_TABLE=.
Without the option, no EAMTable code is compiled.

#+attr_rgpot: compile
#+begin_src cpp
#include "rgpot/EAMTable/EAMTablePot.hpp"

rgpot::EAMTablePot pot({.path = "CuNi.eam.alloy",
                        .format = rgpot::EAMTableFormat::Setfl,
                        .periodic = true,
                        .stress = true});
#+end_src

=read_eam_table= parses a stream into an =EAMTable=, and a second constructor
takes that table directly.

* From the C ABI, Rust and Python

A host that links =rgpot-core= and no C++ kernel builds the same potential with
=rgpot_potential_new_eam_table=, declared in =rgpot.h= since C ABI 1.6.
It takes the path, a format code and =periodic=, returns a handle of the usual
kind and reports a refusal as NULL with =rgpot_last_error=; the entry is in
[[file:c_abi.org][C ABI of rgpot-core]].
The format codes are
=RGPOT_EAM_TABLE_AUTO= (the suffix chooses), =RGPOT_EAM_TABLE_FUNCFL=,
=RGPOT_EAM_TABLE_SETFL= and =RGPOT_EAM_TABLE_FINNIS_SINCLAIR=, the rows of the
table above.
C++ calls =rgpot::PotentialHandle::eam_table=, which throws =rgpot::Error=
instead of returning NULL.

The Rust crate holds its own evaluation of the table, in
=rgpot_core::eam_table=, because =rgpot-core= links no C++ kernel and the handle
must work in a build that has none.
=EamTablePotential::open(path, format, periodic)= builds it and
=EamTablePotential::force= returns the energy and the forces.
It repeats the steps of the previous section, so the two implementations are
checked against the same LAMMPS data rather than against each other.
It differs from =EAMTablePot= in what it leaves out: no stress, no pair list and
no per-atom terms.
It visits every pair and takes the nearest image of the partner from rounded
fractional coordinates, so a periodic call needs every face spacing above twice
the cutoff, and the call fails with =RGPOT_INVALID_PARAMETER= for a smaller
cell.

Python builds the C++ potential, not the Rust one:
=rgpot.EAMTablePot(file, format)= is in [[file:python_api.org][the Python API]].

* Agreement with LAMMPS

The tables go through the steps of =src/MANYBODY/pair_eam.cpp=, so a file gives
the LAMMPS energy and forces to rounding.

- A =Funcfl= file is resampled by four-point Lagrange interpolation onto
  =lround((N - 1) d / d)= points, one fewer than the file lists, as
  =PairEAM::file2array= does for a single file.
- The pair term of a =Funcfl= file is ~r phi = 27.2 * 0.529 * Z(r)^2~ in eV
  Angstrom.
  27.2 is the Hartree in eV and 0.529 the Bohr radius in Angstrom, the rounded
  values LAMMPS uses.
- Each array becomes the seven-coefficient cubic of =PairEAM::interpolate=.
  Its slopes are five-point central differences inside the table, three-point
  central differences at the second and second-to-last points, and one-sided
  differences at the ends.
- Above ~rhomax = (Nrho - 1) drho~ of the file, the energy adds
  ~F'(rho) (rho - rhomax)~ with the slope at the last table point.
  Above the last distance point, both the value and the slope are those at the
  end of the table.
- A pair counts when r is below the cutoff on the grid line.

Two choices differ from LAMMPS.
An atom picks its element by atomic number, matched against the first field of
each element line, where LAMMPS maps types to the element names on line 4.
A file whose element lines do not carry atomic numbers cannot be used as it is.
Only one =Funcfl= file is read, so the LAMMPS mixing of several =.eam= files is
not available.
The =eam/he= and =eam/cd= layouts are not read.

Periodic evaluation sums every image of a pair that lies inside the cutoff.
When every face spacing is greater than twice the cutoff, that image is the
minimum image, and =forceImpl= walks the stored neighbour list.
When a face spacing is at most twice the cutoff, a pair can have several
images inside the cutoff, and an atom can see a translation of itself.
=forceImpl= then walks those images directly and does not build the stored
list.
The walk refuses a cell whose image extent on one axis would pass 1024, and a
cell whose three axes together would visit more than 262144 lattice shifts
for one pair.
The constructor does not check the cutoff against a cell.
It throws =std::invalid_argument= for a file it cannot open or parse.
=forceImpl= throws =std::invalid_argument= when the image extent or the image
count is past that limit, for a periodic call without a cell, for an
atomic number that is in no element line, when a fractional separation is
not finite, and when the nearest integer to that separation plus the image
extent does not fit in an =int= lattice index.

* Stress

=EAMTableConfig::stress= is off by default.
When it is set, =forceImpl= writes the Cauchy stress ~sigma = (1/V) dE/dstrain~
of =stress.hpp= and sets =has_stress=.
The force pass adds ~-fscale * d d^T~ for each pair, as =SuttonChenPot= does,
because the embedding term enters fscale through F'.
With the flag clear, the stress slots and =has_stress= are left as the caller
set them, and the energy and forces are the same bits.
Setting the flag changes =paramsKey()=.

* Pair list

The spline tables and the map from atomic numbers to elements are made once, in
the constructor.
The potential has no setter for them, so they change only with a new potential.
=forceImpl= and =forcePerAtom= keep one =nlist::Neighbours= list of the pairs
within the cutoff plus =EAMTableConfig::skin= (1 Angstrom by default), and reuse
it while every atom stays within half the skin of where it was at the last
build.
The image walk does not build or reuse that list.
The move is measured to the nearest periodic image, so atoms that the caller
wraps back into the cell keep the list.
A new cell, another atom count, or a move past half the skin rebuilds it.
Another element on a site does not, as the list holds positions only.
The pairs within the cutoff are visited in the same order with any skin, so the
skin changes how often the list is built, not the bits of the result, and it is
not part of =paramsKey()=.
=skin = 0= rebuilds the list whenever an atom moves.
=setNeighbourMode(nlist::Mode::Stream)= walks the cells on every call and keeps
no list.
=listReused()= tells whether the last call kept the list and =listBuilds()=
counts the builds.

The list is scratch that each call rewrites, so =caps().reentrancy= is
=Reentrancy::PerInstance=, as for the other potentials that keep one: give each
thread its own instance.
The two stages of =Staged.hpp= run on the host's list and do not touch it.

* Checks

=EAMTablePotTest= compares rgpot with LAMMPS version 22 Jul 2025.
=CppCore/tests/data/eam_table/make_lammps_ref.py= writes two references from
files in the LAMMPS =potentials= directory, copied unchanged.

- =Cu_u3.eam=, a =Funcfl= file for copper from Foiles, Baskes and Daw, Physical
  Review B 33, 7983 (1986).
  It has 500 points in rho and in r and a cutoff of 4.95 Angstrom.
- =CuNi.eam.alloy=, a =Setfl= file for copper and nickel from Onat and
  Durukanoglu, Journal of Physics: Condensed Matter 26, 035404 (2014).
  It has 500 points in rho and in r and a cutoff of 6.394332378 Angstrom.

The =Cu_u3= case is a jittered 108-atom fcc copper cell in a cubic box.
The =CuNi= case is a jittered 256-atom fcc cell in a sheared box, with nickel or
copper at random on each site.
A third case takes the Sutton-Chen platinum row as LAMMPS saw it.
=CppCore/tests/data/sutton_chen/make_lammps_ref.py= writes that row as a
50001-point =eam/fs= table, and the case compares with its cubic reference.

| Case           | LAMMPS style | energy gap (eV) | largest force gap (eV/Angstrom) | largest stress gap (eV/Angstrom^3) |
|----------------+--------------+-----------------+---------------------------------+------------------------------------|
| =Cu_u3= cubic  | =eam=        |         2.3e-12 |                         8.1e-15 |                            7.3e-17 |
| =CuNi= sheared | =eam/alloy=  |         3.1e-12 |                         1.7e-14 |                            1.5e-16 |
| Pt cubic       | =eam/fs=     |         1.7e-12 |                         5.1e-12 |                            1.0e-14 |

The test asks for 1e-10 eV, 1e-10 eV/Angstrom and 1e-13 eV/Angstrom^3.
The test rebuilds the Sutton-Chen table in C++ from the formulas of that script
rather than reading a file.

=[skin]= follows the sheared =CuNi= cell through small moves, atoms shifted by
cell vectors and wrapped back, another element on some sites, one atom past half
the skin, a strained cell and one atom fewer.
After each step the potential with its 1 Angstrom skin gives the energy, the
forces, the stress and the per-atom energies and virials of a potential with
skin 0 to the bit, and =listReused()= and =listBuilds()= show a rebuild exactly
for the move past the skin, the strain and the atom count.
On a free =Cu_u3= cluster the kept list matches skin 0 to the bit and a stream
within 1e-10 eV and eV/Angstrom.

A two-element =eam/fs= table of constants checks the order of the density
blocks.
The A-A, A-B and B-B dimers give -2, -11 and -28 in the documented order.
Reading the sections or the blocks inside a section the other way round changes
at least one of them.

* The copper vacancy

=rgpot-core/tests/eam_table.rs=, =rgpot-core/tests/c/eam_table_capi.c= and =EAMTableHandleTest= evaluate 107 copper atoms around one vacancy through the Rust wrapper, the C ABI and the C++ handle, and compare with LAMMPS version 22 Jul 2025 (20250722), =pair_style eam=
with =pair_coeff * * Cu_u3.eam=.
=CppCore/tests/data/eam_table/make_vacancy_ref.py= writes =cu_u3_vacancy.ref=.
The script takes the 108 sites of a 3 x 3 x 3 fcc cell with a = 3.615 Angstrom,
moves every atom by a uniform random amount up to 0.12 Angstrom in each
coordinate (seed 23), removes the first atom, and runs LAMMPS with
=units metal=, =atom_style atomic=, =boundary p p p=, =neighbor 1.0 bin= and
=run 0=.
The cell is a 10.845 Angstrom cube, so every face spacing is 2.19 times the 4.95
Angstrom cutoff.
The file is
=Cu_u3.eam= with sha256 =3436c491a4c75ea8b7141adbc6ee382a118f5fdb47f609c2a660fc1eb772599f=, the copy in the LAMMPS =potentials= directory that =CppCore/tests/data/eam_table=
holds.
The energy is -371.54901154618921 eV.

| Case          | energy gap (eV) | largest force gap (eV/Angstrom) |
|---------------+-----------------+---------------------------------|
| Vacancy cell  |         4e-13   |                         6e-15   |

The tests ask for 1e-11 eV and 1e-12 eV/Angstrom.
