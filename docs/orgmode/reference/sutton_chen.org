* Sutton-Chen potential

=SuttonChenPot= evaluates

#+attr_rgpot: skip the energy formula, not code
#+begin_example
E = epsilon * [ 1/2 sum_i sum_{j != i} (a / r_ij)^n
                - c * sum_i sqrt(rho_i) ]
rho_i = sum_{j != i} (a / r_ij)^m
#+end_example

The form is Sutton and Chen, Philosophical Magazine Letters 61, 139 (1990),
doi:10.1080/09500839008206493.
The default parameters are the reduced gold and platinum set: =n = 10=, =m = 8=,
=c = 34.408=, =epsilon = 1=, =a = 1=.
Doye and Wales use that set for the 10-8 cluster tables and write it on the
first line of each deposited point file.
The deposited Pt38 Oh geometry gives -10117.2454 and the Pt75 D5h geometry gives
-20431.3452, in units of epsilon, to the four digits printed in the 10-8 table.

Cagin, Dereli, Uludogan, and Tomak, arXiv:cond-mat/9709114, Table I, reprint the
Sutton-Chen rows and cite Sutton and Chen 1990 as their reference 1.
Platinum is epsilon = 1.98330e-2 eV, a = 3.92 Angstrom, c = 34.408, m = 8, n = 10.
Gold on the same row is epsilon = 1.27930e-2 eV, a = 4.08 Angstrom, with the
same c, m, and n.
Those two rows are =sutton_chen_platinum= and =sutton_chen_gold=.
The bulk nearest-neighbor distance and the cohesive well depth are
=sutton_chen_scales=.
The length is the static fcc minimum.
The depth is minus the energy per atom there. c is fitted to zero pressure at
the lattice parameter, so the minimum is a / sqrt(2) for every row of the Cagin
table.
The reduced 10-8 well is 295.4645 epsilon, which is 5.860 eV for platinum and
3.780 eV for gold.

The default cutoff is 40 in the coordinate unit, with no energy shift.
=cutoff = 0= keeps every pair.
Cluster evaluation does not fold the cell.
Periodic evaluation uses the minimum image and needs a positive cutoff and a
cell; otherwise it throws =std::invalid_argument=.
Pairs come from the shared neighbour layer (=nlist::updateCells=), with a skin
of one fifth of the cutoff, or none in =nlist::Mode::Stream=.
With =cutoff = 0= the layer searches without a bound: it bins nothing, stores no
list, and each pass takes the pairs straight from the coordinates, in the order
of the one bin that a search wider than the cluster gives.
A call on fewer than 8192 atoms (=rgpot::kTeamMinAtoms=) runs on the calling
thread whatever =OMP_NUM_THREADS= asks for, since starting a team costs more
than such a call.
From 8192 atoms up each atom keeps the energy and strain of its pairs with
higher-index partners, and the atoms are added in index order.
On a stored neighbour list with at least 8192 atoms and at least 4096 candidate
upper pairs, a team of =OMP_NUM_THREADS= threads runs one three-phase OpenMP
region over an upper-pair index when =total_up <= term_limit= and
=pairScratchFits(total_up, atoms, scratch_avail)= holds: phase 0 evaluates each
upper pair once across work-balanced atom slices rounded to 8-atom boundaries,
phase 1 accumulates per-atom densities and embedding weights in pair-index
order, and phase 2 sums forces, stress, and per-atom virials from the stored
pair terms.
=pairScratchFits= checks that the per-slot vectors fit within half of
=nlist::availableBytes()= (or allows the path when =availableBytes()= returns
0): 69 bytes per candidate upper pair (=active= 1 byte +
=pair_phi= 8 + =pair_force= 48 + =up_j= 4 + =lo_refs= 8), or 77 bytes when
=atoms.energy= is non-null (=pair_he= adds 8).
Per-atom vectors (=up_off=, =lo_off=, =rho=, =weight=, =row_e=, =row_emb=, and
=row_s= with stress) are =O(nAtoms)=, already bounded by =Neighbours::buildCells= and present as =rho_=
and =weight_= on the two-pass walk, so they are not counted against the
pair-slot budget; the per-call scratch vectors in the thread-local workspace are
released when the three-phase call finishes while the half-pair index and slice
splits stay cached for Verlet reuse.
When
=est_half_pairs > term_limit= the three-phase path is skipped before =buildStoredHalfIndex=, and when =total_up > term_limit=
or =pairScratchFits= refuses the call falls back to the threaded two-pass row
walk.
Sparser stored lists stay on one thread, and streaming or unbounded walks still
evaluate each atom's row on its owning slice.
The energy, the forces, the stress and the per-atom terms therefore keep the
bits of one thread on any thread count, also when the runtime starts fewer
threads.
On the two-pass walks, one pass builds the densities and a second pass writes
the forces.
The density pass keeps the powers and =1/r^2= that the force of each pair takes
in =PairTerms<3>= (24 bytes per pair), and the force pass reads them back
instead of raising the distance to =n= and =m= in the second pass.
With =a = 1= those are the density's own powers; otherwise the force's powers of
=a^2 (1/r^2)= are kept, since they can differ from those of =a^2 / r^2= in the
last bit.
=SuttonChenPot::setPairTermLimit= takes a pair count =pairs=, defaulting to
=PairTerms<3>::kDefaultLimit= (1398101 pairs, which is 32 MiB of two-pass
=PairTerms<3>= storage at 24 bytes per pair): it requires =total_up <= pairs= on
the three-phase stored path and caps the two-pass =PairTerms<3>= buffer at
=pairs / lanes= per lane, while the two-pass force pass computes the terms of
any pairs past the kept room from the coordinates, with the same bits.

=rgpot_sutton_chen_energy_forces= is the C entry point.
It takes an =rgpot_sc_config= and writes one energy and one force array.
Each thread keeps the potential of its last call in =rgpot::Kept=
(=rgpot/KeptPotential.hpp=), so a call with the same parameters and atom count
reuses its neighbour update and the room for the pair terms.
Any other call drops that potential and builds a new one, and so does a call
that throws.

* Reduced cluster pairs

=rgpot_lj_gradient= and =rgpot_morse_gradient= return the energy gradient of an
unshifted cluster.
=rgpot_lj_curvature_pairs= fills energy, slope, and curvature for a list of
squared distances in one call.
The =rgpot-pair= crate exposes the same trees as =lj_unit= and =morse_unit=,
which a Rust caller can inline.
The unit Lennard-Jones branch is the direct inverse-power tree, with contraction
off, so a search sees the same rounding as that expression.

* Stress

=SuttonChenConfig::stress= is off by default.
When it is set, =forceImpl= writes the Cauchy stress ~sigma = (1/V) dE/dstrain~
into =ForceOut::stress= in row-major order.
It also sets =has_stress= to 1, and =caps().stress= is true.
The units are energy over length cubed, eV/Angstrom^3 for the
=sutton_chen_platinum= and =sutton_chen_gold= rows.
The sign is that of =stress.hpp=: a compressed crystal has negative diagonal
entries, and the pressure is minus a third of the trace.
A cell with no positive volume, such as a cluster with a null box, leaves
=has_stress= at 0.

The force pass writes the stress as well, because the energy depends on
positions only through pair distances.
With ~d = r_i - r_j~ and a force ~fscale * d~ on atom i, each pair adds
~-fscale * d d^T~ to dE/dstrain.
That fscale already includes the embedding term, so the stress needs no third
loop.
Thompson, Plimpton and Mattson give the many-body virial under periodic
boundaries.
Their paper is in the Journal of Chemical Physics 131, 154107 (2009).

With the flag clear, =forceImpl= leaves the stress slots and =has_stress= as the
caller set them.
=caps()=, =paramsKey()=, the energy and the forces are then the same bits as
before the flag existed.
Setting the flag changes =paramsKey()=, so a cached result without stress is not
served to a caller that asked for one.
The C entry point =rgpot_sutton_chen_energy_forces= and =rgpot_sc_config= do not
carry the flag.

Periodic evaluation keeps one image of each partner.
The stress, like the energy, is the whole sum only while the cutoff is under
half the smallest face spacing of the cell.

** Checks

=SuttonChenPotTest= compares the platinum row with the Large-scale
Atomic/Molecular Massively Parallel Simulator (LAMMPS), version 22 Jul 2025.
LAMMPS runs the potential as =pair_style eam/fs=, the embedded atom method (EAM)
style for Finnis-Sinclair tables.
=CppCore/tests/data/sutton_chen/make_lammps_ref.py= writes the table and the two
108-atom references, with a cutoff of 5.5 Angstrom.

| Cell    | energy gap (eV) | largest force gap (eV/Angstrom) | largest stress gap (eV/Angstrom^3) |
|---------+-----------------+---------------------------------+------------------------------------|
| cubic   |         3.4e-13 |                         2.0e-11 |                            8.3e-14 |
| sheared |         2.2e-12 |                         2.8e-11 |                            2.0e-13 |

Tables of 12501, 25001 and 50001 points move the LAMMPS stress by at most
5.8e-13 eV/Angstrom^3, so the gaps above are not set by the table.
The test also takes each Voigt component as a central difference of the energy
under a symmetric strain of 1e-6.

The last test takes the pressure of the perfect face-centered cubic (fcc)
platinum crystal at the lattice parameter ~a = 3.92~ Angstrom.
Sutton and Chen fit c to zero pressure of the infinite crystal at a.
Their ~c = 34.408~ is that zero-pressure value rounded to three decimals.
The fcc lattice sum with ~n = 10~ and ~m = 8~ gives ~c = 34.408374~.
The published c therefore leaves about 0.0015 GPa in the infinite crystal at a.
With the cutoff at 0.49 of the cell edge, rgpot gives

| Atoms | Cutoff (Angstrom) | Pressure at a (GPa) | Pressure at 0.99 a (GPa) |
|-------+-------------------+---------------------+--------------------------|
|   256 |            7.6832 |              0.0864 |                   9.3308 |
|   864 |           11.5248 |              0.0155 |                   9.2560 |
|  2048 |           15.3664 |              0.0053 |                   9.2446 |
|  4000 |           19.2080 |              0.0027 |                   9.2423 |

The pressure at a falls toward that 0.0015 GPa as the cutoff grows, not toward
zero.
The test asks it to shrink from 256 to 2048 atoms and to stay under 1e-3 of the
stress at 0.99 a, about 0.009 GPa.

** Cost

Pinned to one core, the flag adds 5.9 to 8.5 percent to a call.
A jittered 864-atom cell at a cutoff of 7 Angstrom takes about 880 ns per atom
without the stress and 930 with it.
A 4000-atom cell with a cutoff of 19 Angstrom takes about 25800 and 27500.
With the flag clear, six cases from 108 to 4000 atoms take the same time as
before the flag existed, to within 4 percent.

** C entry points

=rgpot_sutton_chen_energy_forces= does not carry the stress flag.
=box= may be null when =periodic= is 0.
Each thread keeps the potential of its last call when the parameters and the
atom count match.

*** =rgpot_sc_config=

- Inputs :: =epsilon=, =c=, =a=, =n=, =m=, =cutoff= and =periodic=.
  Field order is part of the ABI.
- Units :: =epsilon= sets the energy unit and =a= the length unit.
  =cutoff= is in the coordinate unit.
  =c=, =n=, =m= and =periodic= are dimensionless.
- Outputs :: the parameter block of =rgpot_sutton_chen_energy_forces= and
  =rgpot_sutton_chen_scales=.
- Errors :: none.
  The call that reads the block reports a bad value.

*** =rgpot_sutton_chen_energy_forces=

#+attr_rgpot: signature
#+begin_src c
int rgpot_sutton_chen_energy_forces(const rgpot_sc_config *cfg,
                                    int32_t natoms, const double *positions,
                                    const double *box, double *energy,
                                    double *forces);
#+end_src

- Inputs :: =cfg=, =natoms=, positions (3 =natoms= doubles), =box= (nine
  doubles, one cell vector per row) and the energy and force pointers.
- Units :: positions, =box= and =cutoff= in the coordinate unit.
  Energy in the unit of =epsilon=, forces in energy per length.
- Outputs :: one energy and 3 =natoms= forces, which are minus the gradient.
  Returns 0 on success.
- Errors :: returns 1 when =cfg= or =energy= is null, =natoms= is negative,
  =natoms= is positive and =positions= or =forces= is null, or the config is
  rejected.
  A periodic call also returns 1 when the cutoff is not positive or the cell is
  not usable.

*** =rgpot_sc_scales=

- Inputs :: =nearest_neighbor= and =well_depth=.
- Units :: =nearest_neighbor= in the coordinate unit.
  =well_depth= in the energy unit, and it is positive.
- Outputs :: the bulk scales written by =rgpot_sutton_chen_scales=.
- Errors :: none.

*** =rgpot_sutton_chen_scales=

#+attr_rgpot: signature
#+begin_src c
int rgpot_sutton_chen_scales(const rgpot_sc_config *cfg,
                             rgpot_sc_scales *out);
#+end_src

- Inputs :: =cfg= and =out=.
- Units :: as =rgpot_sc_config= and =rgpot_sc_scales=.
  The length is the static fcc minimum and the depth is minus the energy per
  atom there.
- Outputs :: the two scales.
  Returns 0 on success.
- Errors :: returns 1 when =cfg= or =out= is null, or when the config is
  rejected.
