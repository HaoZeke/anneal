* C ABI of rgpot-core

=rgpot-core/include/rgpot.h= carries two identities.
The package version
(=RGPOT_VERSION=, =RGPOT_VERSION_MAJOR=, =RGPOT_VERSION_MINOR=, =RGPOT_VERSION_PATCH=)
follows the crate.
The ABI stamp follows the layout of the exported structs and the signatures of
the exported functions, and does not move with the package version.
A consumer that loads =librgpot= at run time checks the stamp.

** Stamp

#+begin_src c
typedef struct rgpot_abi_stamp_t {
  uint16_t abi_major;
  uint16_t abi_minor;
  uint16_t layout_revision;
} rgpot_abi_stamp_t;

#define RGPOT_ABI_VERSION_MAJOR 1
#define RGPOT_ABI_VERSION_MINOR 2
#define RGPOT_ABI_LAYOUT_REVISION 1

rgpot_abi_stamp_t rgpot_abi_stamp(void);
int32_t rgpot_abi_compatible(const rgpot_abi_stamp_t *stamp);
#+end_src

The macros hold the stamp of the header the caller compiled against.
=rgpot_abi_stamp()= returns the stamp of the library actually loaded.
=rgpot_abi_compatible(&stamp)= returns nonzero when the loaded library can serve
a caller built with =stamp=: equal =abi_major=, equal =layout_revision=, and a
library =abi_minor= at least the caller's.
A null pointer returns 0.

#+begin_src c
rgpot_abi_stamp_t built = {RGPOT_ABI_VERSION_MAJOR, RGPOT_ABI_VERSION_MINOR,
                           RGPOT_ABI_LAYOUT_REVISION};
if (!rgpot_abi_compatible(&built)) {
  rgpot_abi_stamp_t have = rgpot_abi_stamp();
  fprintf(stderr, "librgpot ABI %u.%u layout %u, built against %u.%u layout %u\n",
          have.abi_major, have.abi_minor, have.layout_revision,
          built.abi_major, built.abi_minor, built.layout_revision);
  abort();
}
#+end_src

** Bumping the numbers

The numbers live in =rgpot-core/src/version.rs= as
=RGPOT_ABI_VERSION_MAJOR=, =RGPOT_ABI_VERSION_MINOR= and
=RGPOT_ABI_LAYOUT_REVISION=.
Regenerate the header with =pixi run gen-header= and commit it with the change.
The crate test =committed_header_matches_the_crate= fails when the header and
the source disagree.

- =abi_major=: increment for a change a caller built against the old header
  cannot survive: removing or renaming an exported function, changing a
  signature, changing the meaning of an existing argument or status code.
  Reset =abi_minor= to 0.
- =abi_minor=: increment for an additive change that leaves every old call
  valid: a new exported function, a new status code, a new enum value a caller
  may ignore.
  A caller built against minor N runs on any library of the same major and
  layout revision whose minor is at least N.
- =layout_revision=: increment when the size or field order of an exported
  struct changes, or an existing field changes type, even when every function
  keeps its name.
  A caller and a library with different layout revisions never match, whatever
  their minors.

The ABI numbers do not follow the package version: a release that changes no
exported symbol leaves them where they are.
They are also not the ELF soversion of =librgpot=.
The C API is exported from that library and has no shared library of its own, so
a C caller relinks when the C++ SONAME moves even if these numbers stay.
3.5.0 left them at 1, 0 and 1.
3.6.0 carries 1, 1 and 1.
=rgpot_eindir_abi_compatible= is the new exported function.
A caller built against minor 0 still matches, and a caller that needs the new
function is refused by a 3.5 library.
No exported C struct in =rgpot.h= changed layout.
3.7.0 still carries 1, 1 and 1.
The next release carries 1, 2 and 1: the Hessian-vector entry points below are
additions, and their state lives behind the opaque cache pointer of the handle,
so =rgpot_potential_t= keeps its layout.
A caller that needs them is refused by a 3.7 library.

=scripts/abi_core_baseline.txt= lists the =rgpot_*= functions the =rgpot-core=
shared library exports in a default build.
The meson test =abi_core_symbols= fails when one of them is no longer exported,
and the crate test =the_abi_baseline_is_declared_by_the_header= when the
committed header stops declaring one.
The list only grows: append a new function with the minor bump that adds it.
=scripts/abi_baseline.txt= is the same check for the neighbour-list and
fast-list exports of =librgpot= (meson test =abi_symbols=).
The neighbour-list C ABI is separate.
3.6.0 sets it to version 4 (=RGPOT_NLIST_ABI= in =rgpot_nlist.h=).
=rgpot_nlist_request_init= sets the defaults, =bytes= is the struct size, and =rgpot_nlist_strerror=
names a code.
3.6.0 also bumps the ELF soversion of =librgpot= from the soversion 4 of 3.5.1.
Soversion 5 records LJPot and MorsePot each holding a neighbour list and a
cached pair table.
Soversion 6 is what this release ships.
LJ and Morse no longer keep a copied half-list, and ZBL and the open
Lennard-Jones cluster hold a neighbour list.
A caller built against soversion 4 does not load =librgpot.so.6=.
=librgpot_mpi= stays at soversion 3.

** C++ layout stamp

The stamp above covers the C interface of =rgpot-core=.
The header-only C++ classes are a second boundary: a consumer compiles
=Potential=, the force structures and the pair potentials, and the library
supplies their out-of-line members.
A library built from another revision of those headers, or with another value of
=RGPOT_HAS_CACHE=, carries the same C stamp and still runs with the wrong
offsets or the wrong vtable.
=rgpot/abi/CxxLayout.hpp= stamps that boundary.
It needs neither =rgpot.h= nor the Rust core, so every build of =librgpot=
exports it.

#+begin_src cpp
#include "rgpot/abi/CxxLayout.hpp"

if (!rgpot::abi::layout_compatible()) {
  // the loaded library was built from other layouts than these headers
}
#+end_src

- =rgpot::abi::header_stamp()= is a =constexpr= of the header: the stamp the
  consumer compiled against.
- =rgpot::abi::library_stamp()= calls the exported =rgpot_cxx_layout_stamp()=:
  the stamp of the loaded library.
- =rgpot::abi::layout_compatible()= is true when the revision, the feature bits
  and the hash are equal.
- =rgpot_cxx_layout_compatible(const rgpot_cxx_layout_stamp_t *)= is the same check for a caller that holds only the C struct =(uint32_t revision, uint32_t features, uint64_t hash)=.
  The C stamp struct of =rgpot.h= does not change.

The hash folds =sizeof=, =alignof= and, for plain structures, =offsetof= of each
covered type, plus the pointer width.
Feature bit 0 is =RGPOT_HAS_CACHE=, which adds a virtual to =PotentialBase= and
changes =Potential=.

Covered types:

- =ForceInput=, =ForceOut=, =ForceBatch=, =PotCaps=, =CalculatorGroup=
- =LJConfig=, =LJClusterConfig=, =MorseConfig=, =ZBLConfig=
- =Reentrancy= and =PotType= (width, and the values of the enumerators consumers
  switch on)
- =PotentialBase=, =Potential<Derived>= (through one probe instantiation),
  =LJPot=, =LJClusterPot=, =MorsePot=, =ZBLPot=
- with the cache: =cache::EvalCounts= and =cache::PotentialCache=

Not covered: the classes of optional backends (xtb, tblite, dftd3, dftd4,
ExprPot, XcKernel, Metatomic, UMA, NWChem, CPMD, MOPAC, Skala, the Fortran
potentials).
Their headers and features differ between builds, so a stamp over them would
refuse libraries that agree on everything a consumer uses.
The plugin interface carries
=RGPOT_PLUGIN_API_VERSION=, and the engine libraries carry =rgpot_engine_abi_version()=.

*** Bumping

- A change to the size, alignment or a field offset of a covered type moves the
  hash by itself.
  Bump =kCxxSoversion= in the same change.
  That constant is the ELF soversion of =librgpot= (=librgpot.so.N=).
  Meson and CMake read it, so the SONAME is not written down anywhere else.
  The hash is not the SONAME.
  It depends on the platform tag (=kCxxPlatformTag=): operating system,
  architecture, standard library and data model.
  It also folds pointer width and the cache feature bit, so two builds of one
  revision do not share a hash.
  Record each no-cache hash in =kCxxSoversionTable= in
  =CppCore/rgpot/abi/CxxLayout.hpp=.
  =CxxLayout.cc= static_asserts the row for the platform it is compiled on.
  A platform with no row does not fail the build.
  The compiler prints that the tag is unlisted.
  =CppCore/tests/check_cxx_soversion.py= fails a live hash only when that tag is
  in the table.
  It fails when the fingerprint differs from
  =CppCore/rgpot/abi/cxx_soversion_ledger.txt=, and when a shipped ledger line
  changes under the same soversion.
  Append a line to that ledger with the new soversion and the fingerprint the
  check prints.
  The fingerprint is platform-independent.
  Do not edit a shipped line.
- =kCxxLayoutRevision= in =CppCore/rgpot/abi/CxxLayout.hpp=: increment when a
  change keeps every size and offset and still alters the ABI.
  Reordering virtual functions, changing the meaning of a field, changing a base
  class, changing a default member initializer a consumer inlines.
  Bump =kCxxSoversion= in that change as well: the revision is an input of the
  hash.
- =kPotentialBaseVirtuals=, =kPotentialBaseCacheVirtuals= and
  =kPotentialVirtuals= count the virtual functions of the polymorphic classes,
  because the compiler hides a vtable change from =sizeof=.
  =CppCore/tests/check_virtual_counts.py= counts the =virtual= declarations in
  =Potential.hpp= and fails when a count is stale.
  Update the constant and increment =kCxxLayoutRevision= together.
- Adding a covered type changes the hash, so it needs no revision bump.
  Add it to =detail::compute_hash()= in the same commit, and bump
  =kCxxSoversion= with the hash.

*** Updating the platform table

=kCxxSoversionTable= starts empty when the soversion changes, and is filled from
CI.
Do not copy a hash from another platform or from a local build.

Each CI build of the printer prints one =RGPOT_CXX_LAYOUT_STAMP= line.
It carries =tag=, =hash=, =hash_dec=, =features= and =revision=.

=features= is 1 for a cache build.
Ignore those lines.
The no-cache hash is the one that goes in the table.

The workflow "C++ layout stamp" compiles
=CppCore/tests/print_cxx_layout_stamp.cc= on Linux x86_64, Linux aarch64, macOS
arm64, macOS x86_64 and Windows MSVC.
The Linux and macOS wheels print the same line from the compiler that builds the
wheel.
The Meson =CxxSoversion= test runs the printer too.
There is no musl row unless a log prints a =linux-musl-= tag. librgpot wheels
skip musllinux, and the musl potctl build does not compile this header.

When the soversion is bumped:

1. Increment =kCxxSoversion=.
2. Leave =kCxxSoversionTable= empty and delete the listed-platform guards, so
   every platform builds and the printers run.
3. Read each =RGPOT_CXX_LAYOUT_STAMP= line whose =features= is 0.
4. Add one table row per distinct tag, using that line's =hash= as
   =0x<hash>ull=.
   Add a matching guard.
   The guard is an =#if=, then =#elif=, on =RGPOT_OS_*=, =RGPOT_ARCH_*=,
   =RGPOT_STDLIB_*= and =RGPOT_MODEL_*=.
   Inside the branch, define
   =RGPOT_CXX_PLATFORM_LISTED= as 1 and =RGPOT_CXX_PLATFORM_LISTED_TAG= as that
   same tag string.
5. Append one ledger line: the new soversion and the fingerprint the check
   prints.
   Do not edit a shipped line.
6. Push and wait until the jobs that printed the hashes are green.
   A listed tag whose live hash differs fails the build.

The fixture =CppCore/tests/layout_fixture.cc= is a shared object built from a
header in which =ForceOut= gained a field; =CxxLayoutTest= requires that its
stamp differs and that its compatibility check refuses the real stamp.

=kCxxSoversion= applies to =librgpot= only.
=librgpot_mpi= stays at soversion 3: its C ABI is =RGPOT_MPI_ABI_VERSION= 1.
The engine plugins (=libclassical_engine.so=, =libmopac_engine.so=,
=libnwchem_engine.so=, =libskala_engine.so=,
=libxtb_engine.so=, =libmetatomic_engine.so=,
=libuma_engine.so=) are opened by those unversioned names and keep =RGPOT_ENGINE_ABI_VERSION= 1.
The =libpot_client_bridge= header did not change.
=librgpot_cuh2= only added =rgpot_cuh2_force_ws=.
The pair-potential types whose layouts changed are static objects inside
=librgpot=, so they have no SONAME of their own.
CMake's =libptlrpc= is the same: the schema it carries is the 3.5.0 schema, and
Meson does not install it as a separate shared library.

** Scope

The first stamp covers the C surface of =rgpot-core=.
The C++ and Python packages do not re-export it; the C++ classes have the layout
stamp above.
The engine plugins carry their own number, =rgpot_engine_abi_version()=.
The eindir objective keeps
=rgpot_eindir_abi_stamp()=, which reports the stamp of =eindir-core=, and =rgpot_eindir_abi_compatible()=,
which checks a stamp against the =eindir-core= compiled into the loaded library.

#+begin_src c
eindir_abi_stamp_t rgpot_eindir_abi_stamp(void);
int32_t rgpot_eindir_abi_compatible(const eindir_abi_stamp_t *stamp);
#+end_src

=rgpot_eindir_abi_compatible= returns what =eindir_core_abi_compatible= returns
for the same stamp: nonzero for an equal =abi_major=, =objective_layout=,
=objective_size=, =objective_align= and =dlpack_major=, an =abi_minor= and a
=dlpack_minor= no newer than the library's, and no feature bit the library
lacks.
A null pointer returns 0.
A caller that links only =librgpot= uses it instead of resolving
=eindir_core_abi_compatible= itself.

** Hessian-vector products

A minimum-mode search (Lanczos, dimer) applies the Hessian =H= of the energy
to many directions =v= at one geometry.
With only a force callback each product is a difference of two force
evaluations, and one of them is the centre the search has not moved from.
A potential handle answers =H v= itself and keeps the forces of that centre.

#+begin_src c
typedef enum rgpot_hvp_scheme_t {
  RGPOT_HVP_AUTO = 0,     /* analytic if registered, else forward */
  RGPOT_HVP_FORWARD = 1,  /* (F(x) - F(x + h u)) |v| / h */
  RGPOT_HVP_CENTRAL = 2,  /* (F(x - h u) - F(x + h u)) |v| / 2h */
  RGPOT_HVP_ANALYTIC = 3, /* the registered callback */
} rgpot_hvp_scheme_t;

#define RGPOT_HVP_DEFAULT_STEP 1.0e-3

rgpot_status_t rgpot_potential_hvp(const rgpot_potential_t *pot,
                                   const rgpot_force_input_t *input,
                                   const double *direction, double step,
                                   int32_t scheme, double *hv_out);
rgpot_status_t rgpot_potential_hvp_centre(const rgpot_potential_t *pot,
                                          const rgpot_force_input_t *input,
                                          rgpot_force_out_t *output);
#+end_src

=direction= and =hv_out= hold =3 * n_atoms= doubles laid out like the positions
and must not overlap.
=u = v / |v|= and =step= is the displacement =h= along it, in the units of
the positions; 0 selects =RGPOT_HVP_DEFAULT_STEP=.
The difference is scaled back by =|v|=, so the product does not depend on the
length of =direction= beyond that factor.
A zero direction writes zeros and makes no call.

| Scheme               | Force calls per product      | Error          |
|----------------------+------------------------------+----------------|
| =RGPOT_HVP_FORWARD=  | 1, and 1 for each new centre | =O(h)=         |
| =RGPOT_HVP_CENTRAL=  | 2                            | =O(h^2)=       |
| =RGPOT_HVP_ANALYTIC= | 0                            | the callback's |

=k= forward products at one centre therefore cost =k + 1= force calls
instead of =2k=.
No finite difference makes one call per product at =O(h^2)=.
The forward error is =(h/2) T(u, u) |v|=, with =T= the third derivative of the
energy, and cancelling it takes the second evaluation that the central scheme
makes.
A search that needs second-order products at one call each registers an
analytic product.
The forward product is positively homogeneous in =direction= but not odd: the
=O(h)= term keeps its sign when =v= does not.

The centre is keyed on the bits of the positions, the atomic numbers and the
cell, so moving one coordinate by one ulp, changing the cell or a species, or
passing =-0.0= for =0.0= computes a new centre.
=rgpot_potential_hvp_centre= returns the energy and an owning forces tensor
from the same cache, and makes the force call when the centre is new.
A search that needs the centre forces asks there instead of
=rgpot_potential_calculate=, so the products after it make one call each.
=rgpot_potential_hvp_invalidate= drops the centre, for a potential whose
parameters changed while the geometry did not.
The cache is per handle and holds one centre.
It is safe to share between threads, and the last centre computed wins; whether
the force callback may run concurrently is up to the potential, as for
=rgpot_potential_calculate=.

#+begin_src c
typedef rgpot_status_t (*HessianVectorCallback)(void *user_data,
                                                const rgpot_force_input_t *input,
                                                const double *direction,
                                                double *hv_out);
rgpot_status_t rgpot_potential_set_hvp_callback(const rgpot_potential_t *pot,
                                                HessianVectorCallback callback);
#+end_src

A potential that knows its Hessian registers the product with
=rgpot_potential_set_hvp_callback=; it receives the handle's =user_data=.
A null callback clears it.
=RGPOT_HVP_AUTO= then uses it and makes no force call, and =RGPOT_HVP_ANALYTIC=
without one is =RGPOT_INVALID_PARAMETER=.
A non-finite value in the callback's output is refused.
=rgpot::PotentialHandle::from_impl= registers it for a C++ potential with a
=hessianVectorImpl(const ForceInput&, const double*, double*) const= member,
=MorsePot= among them.

=rgpot_potential_hvp_counts= fills =rgpot_hvp_counts_t= with the products
answered, the force calls made, the requests served from the centre and the
analytic products; =rgpot_potential_reset_hvp_counts= zeroes them and keeps the
centre.
The C++ potentials used without the Rust core, the Python module among them,
get the same schemes, step, cache and counts from =rgpot/HessianVector.hpp=.

** Entry points

These names are part of the public C surface.
The coverage check fails when one of them disappears from this book.

- =rgpot_version=, =rgpot_version_major=, =rgpot_version_minor=, =rgpot_version_patch=
  :: the loaded library's package version.
  The pointers from =rgpot_version= are static.
- =rgpot_source_revision= :: git revision recorded at build time, or empty.
- =rgpot_last_error= :: thread-local sentence for the last failed call.
  Do not free it.
  It dies at the next =rgpot_*= call on that thread.
- =rgpot_tensor_cpu_f64_2d=, =rgpot_tensor_cpu_i32_1d=,
  =rgpot_tensor_cpu_f64_matrix3= :: non-owning DLPack views of caller memory.
- =rgpot_tensor_owned_cpu_f64_2d= :: an owning copy.
  Free it with =rgpot_tensor_free=.
- =rgpot_tensor_free=, =rgpot_tensor_device=, =rgpot_tensor_data=,
  =rgpot_tensor_shape= :: deleter and inspectors.
  A null free is a no-op.
- =rgpot_force_input_create=, =rgpot_force_input_free=, =rgpot_force_out_create=
  :: build and release the borrowed input tensors.
  Freeing the input does not free the caller's arrays.
- =rgpot_potential_new=, =rgpot_potential_new_eindir= :: create a handle.
  =rgpot_potential_free= and =rgpot_potential_free_eindir= release it.
  Do not call both on one pointer.
- =rgpot_potential_calculate= :: one energy and force evaluation.
- =rgpot_potential_hvp=, =rgpot_potential_hvp_centre= :: a Hessian-vector
  product and the centre forces it reuses.
- =rgpot_potential_set_hvp_callback= :: register or clear an analytic product.
- =rgpot_potential_hvp_invalidate=, =rgpot_potential_hvp_counts=,
  =rgpot_potential_reset_hvp_counts= :: drop the centre, read and zero the
  counters.
- =rgpot_rpc_client_new=, =rgpot_rpc_calculate=, =rgpot_rpc_client_free=,
  =rgpot_rpc_server_start= :: the Cap'n Proto client and the blocking server.
  They are compiled only when the library was built with RPC.
- =rgpot_nlist_abi_version=, =rgpot_nlist_strerror=, =rgpot_nlist_request_init=
  :: the neighbour query's version, sentences, and the zeroed request.
- =rgpot_nlist_build=, =rgpot_nlist_build_systems= :: fill a caller-owned
  structure of arrays.
  A short buffer returns the needed count.
- =rgpot_nlist_walk_open=, =rgpot_nlist_walk_pull=, =rgpot_nlist_walk_close= ::
  stream pairs without storing the whole list.
  The walk borrows positions until close.
- =rgpot_nlist_builder_open=, =rgpot_nlist_builder_update=,
  =rgpot_nlist_builder_close= :: reuse a list while every atom stays inside half
  the skin.
- =rgpot_nlist_fortran_open=, =rgpot_nlist_fortran_build=,
  =rgpot_nlist_fortran_close= :: the Fortran gather, indices zero-based, vectors
  in Fortran order.
- =rgpot_fast_pairs=, =rgpot_fast_wrap=,
  =rgpot_fast_wrap_axes=, =rgpot_fast_last_error= :: the orthorhombic candidate
  list and the minimum-image wrap.
  A negative code leaves a thread-local sentence.
- =rgpot_plugin_init= :: the one symbol a plugin shared library exports.
