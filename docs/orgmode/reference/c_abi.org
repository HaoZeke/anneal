* C ABI of rgpot-core

=rgpot-core/include/rgpot.h= declares the C ABI of the Rust crate =rgpot-core=.
The header is generated by cbindgen from =rgpot-core/src=.
It includes =dlpack/dlpack.h= and uses =eindir_objective_t= and
=eindir_abi_stamp_t= without declaring them.
A C caller includes
=rgpot/eindir_abi.hpp= first, which declares both; a C++ caller includes =rgpot/c_api.hpp=.
The RPC names are declared only when =RGPOT_HAS_RPC= is defined before the
header.
The neighbour-list, fast-list and plugin symbols of =librgpot= have their own
pages: [[file:nlist_abi.org][Neighbour-list C ABI]],
[[file:fast_nlist.org][Fast neighbour list]] and
[[file:plugin_abi.org][Plugin ABI]].
Why the ABI stamp exists is in
[[file:../explanation/abi-stamps.org][ABI stamps]], and how to bump it is in
[[file:../contributing/developer/abi-bump.org][Bump the ABI numbers]].
The reasons for the Hessian-vector design are in
[[file:../explanation/hessian-vector.org][Hessian-vector products]].

The C ABI converts no units.
Positions and cell are in the length unit of the potential behind the callback,
energy in its energy unit, and forces in energy per length.
The C++ potentials of =librgpot= use Angstrom and eV.

The examples on this page are compiled against the header and not run: a Meson
build exports these functions only when it is configured with =with_rust_core=.

** Errors

*** =rgpot_status_t=

- Inputs :: none; an enum.
- Units :: none.
- Outputs ::
  =RGPOT_SUCCESS= (0), =RGPOT_INVALID_PARAMETER= (1), =RGPOT_INTERNAL_ERROR= (2), =RGPOT_RPC_ERROR= (3), =RGPOT_BUFFER_SIZE_ERROR=
  (4), =RGPOT_SCC_NOT_CONVERGED= (5), =RGPOT_NO_JET= (6), =RGPOT_JET_BRANCH= (7), =RGPOT_JET_DOMAIN= (8).
- Errors :: none.
  The only functions of =rgpot-core= that return =RGPOT_BUFFER_SIZE_ERROR=
  themselves are =rgpot_potential_taylor_jet= and =rgpot_ch5_2008_taylor_jet=,
  for an =order= whose =order + 1= doubles overflow in bytes; a callback may
  return it and it is passed through.
  =RGPOT_SCC_NOT_CONVERGED= is the status of a callback whose engine ran its
  self-consistent field out of iterations; =rgpot_potential_calculate= and the
  Hessian-vector entry points return it unchanged, and
  =rgpot_potential_fused_error_kind= reports the same distinction for the
  eindir path, whose own status type has no such value.

A function wrapped in the crate's panic guard returns =RGPOT_INTERNAL_ERROR= for
a caught Rust panic and stores the panic message.
The guarded functions are =rgpot_potential_calculate=, =rgpot_potential_hvp=,
=rgpot_potential_hvp_centre=, =rgpot_potential_taylor_jet=, =rgpot_rpc_calculate=
and =rgpot_rpc_server_start=.

*** =rgpot_set_last_error=

#+attr_rgpot: signature
#+begin_src c
void rgpot_set_last_error(const char *msg);
#+end_src

- Inputs :: =msg= a NUL-terminated string, or NULL.
- Units :: none.
- Outputs :: the calling thread's =rgpot_last_error()= message is =msg=; NULL
  clears it.
  A callback calls this before it returns an error status, so that the text
  reaches the caller of =rgpot_potential_calculate=, or of the eindir
  functions, which do not store a message for a failed callback.
- Errors :: none; bytes that are not valid UTF-8 are replaced.

*** =rgpot_last_error=

#+attr_rgpot: signature
#+begin_src c
const char *rgpot_last_error(void);
#+end_src

- Inputs :: none.
- Units :: none.
- Outputs :: the message of the last failure recorded on the calling thread,
  NUL-terminated, or the empty string when none was recorded.
  Do not free it.
- Errors :: none; the call cannot fail.

The message is thread-local.
A failing call replaces it; a successful call leaves the previous message in
place, so read it only after a call returned an error.
The header states that the pointer is valid until the next =rgpot_*= call on the
same thread.
A message that contains a NUL byte is stored as
=(error message contained interior NUL)=.
When a callback returns an error status, =rgpot-core= stores no message of its
own: the text is whatever the callback stored, or an older message.

#+attr_rgpot: compile
#+begin_src c
#include <stdio.h>

#include "rgpot/eindir_abi.hpp"
#include "rgpot.h"

int report(const rgpot_potential_t *pot, const rgpot_force_input_t *input,
           rgpot_force_out_t *output) {
  rgpot_status_t s = rgpot_potential_calculate(pot, input, output);
  if (s != RGPOT_SUCCESS) {
    fprintf(stderr, "rgpot error %d: %s\n", (int)s, rgpot_last_error());
    return 1;
  }
  return 0;
}
#+end_src

** Tensors

The tensor functions take and return DLPack =DLManagedTensorVersioned= pointers.
Every tensor they create is on the CPU with device id 0, row-major strides and
DLPack version 1.0.
The borrowing constructors do not check their arguments;
=rgpot_tensor_owned_cpu_f64_2d= and the accessors handle NULL as their entries
say.

** Force input and output

*** =rgpot_force_input_t=

- Inputs :: three borrowed tensor pointers: =positions=
  (=[n_atoms, 3]=, float64), =atomic_numbers=
  (=[n_atoms]=, int32) and =box_matrix= (=[3, 3]=, float64, lattice vectors as

** Potential handles

*** =PotentialCallback=

#+attr_rgpot: signature
#+begin_src c
typedef enum rgpot_status_t (*PotentialCallback)(void *user_data,
                                                 const struct rgpot_force_input_t *input,
                                                 struct rgpot_force_out_t *output);
#+end_src

- Inputs :: =user_data= given to the constructor; =input= the geometry; =output=
  storage whose =forces= is NULL.
- Units :: those of the potential.
- Outputs :: the callback sets =output->forces= to a tensor with a deleter, and
  =output->energy= and =output->variance=; it returns =RGPOT_SUCCESS= or an
  error status.
- Errors :: =rgpot_potential_calculate= returns the callback's status unchanged
  and does not check its output.
  The Hessian-vector entry points and the eindir evaluation path check the
  output: =forces= must be a float64 CPU tensor of
  =3 * n_atoms= finite elements, one- or two-dimensional, C-contiguous and aligned, and =energy= must be finite; otherwise the call fails with =RGPOT_INVALID_PARAMETER= (=EINDIR_INVALID_PARAMETER=
  on the eindir path).

The function pointer is not nullable: a NULL callback passed to a constructor is
undefined behaviour.

*** =rgpot_potential_t=

- Inputs :: none; a struct created by =rgpot_potential_new= or
  =rgpot_potential_new_eindir=.
- Units :: =box_matrix= in the length unit of the potential.
- Outputs :: the fields, in order: =base= (an =eindir_objective_t=, first so
  that the handle can be cast to =eindir_objective_t *=), =callback=,
  =pot_user_data=, =pot_free_fn=, =n_atoms=, =atomic_numbers= (owned,
  =n_atoms= values), =box_matrix= (9 doubles, lattice vectors as rows) and
  =fused_cache=.
- Errors :: none.
  Do not write the fields, and do not call =eindir_objective_free= on =base=.

*** =rgpot_fused_cache_t=

- Inputs :: none; an opaque type.
- Units :: none.
- Outputs :: none; it holds the fused cache of one handle (see
  [[#fused-cache][Fused cache]]), the evaluation counters, the peer refusal and
  the Hessian-vector state.
  The handle owns it.
- Errors :: none.

*** =rgpot_eval_counts_t=

- Inputs :: none; a struct filled by =rgpot_potential_eval_counts=.
- Units :: none; counts.
- Outputs :: =computed=, the callback invocations the fused cache made for
  =eindir_objective_eval=, =eindir_objective_grad= and the Hessian-vector
  centre, and =served=, the requests answered from the stored outcome without a
  callback, a stored failure included.
  =rgpot_potential_calculate= does not change either counter.
- Errors :: none.

** Fused cache
:PROPERTIES:
:CUSTOM_ID: fused-cache
:END:

The energy and gradient of the eindir objective, and the centre of the
Hessian-vector products, are one fused evaluation: a callback call returns the
energy and the forces together.
One cache per handle sits in front of the callback and holds one entry.
Its key is the position bits of the request (=f64::to_bits=, so =-0.0= and
=0.0= differ and no tolerance is applied) and a fingerprint of everything else
that changes the answer: the atomic numbers, the cell, the settings installed by
=rgpot_potential_set_fused_settings=, and an epoch that
=rgpot_potential_hvp_invalidate= and a peer refusal advance.
Its value is the outcome of the callback, which is either the energy and
forces, or a failure that records its kind and message.

A request whose key equals the stored key returns the stored outcome without a
callback, whether it is a success or a failure; a request with another key
calls the engine and replaces the entry.
=eindir_objective_eval= and =eindir_objective_grad= both go through this one
path, so a failed energy followed by a gradient at the same positions is one
callback, and the gradient returns the status and the =rgpot_last_error=
message of the first failure.
A failed energy is not retried at the same bits.
A retry that should run the engine again, for example a warm-start retry after
an SCC failure, must change a setting: install new settings with
=rgpot_potential_set_fused_settings=, or call =rgpot_potential_hvp_invalidate=.
Calling again with the same settings returns the stored failure.
The entry lock is held while the callback runs, so concurrent requests for one
key make one callback.
=rgpot_potential_calculate= does not use the cache.

*** =rgpot_fused_error_kind_t=

- Inputs :: none; an enum.
- Units :: none.
- Outputs :: =RGPOT_FUSED_OK= (0), the stored outcome is a success or nothing is
  stored; =RGPOT_FUSED_SCC_NOT_CONVERGED= (1), the callback returned
  =RGPOT_SCC_NOT_CONVERGED=; =RGPOT_FUSED_ENGINE_FAILED= (2), the callback
  returned another error status; =RGPOT_FUSED_INVALID_RESULT= (3),
  the callback reported success with a malformed or non-finite result.
- Errors :: none.

*** =rgpot_fused_settings_t=

** Hessian-vector products

=RGPOT_HVP_DEFAULT_STEP= is 1.0e-3, the step used when a caller passes 0.
The centre is the entry of the [[#fused-cache][fused cache]], so it keys on the
bits of the positions, the atomic numbers, the cell and the installed settings,
and =-0.0= and =0.0= are different centres.
A NULL =atomic_numbers= or =box_matrix= tensor is allowed and is part of the key
as absent.
The cache holds one entry per handle, shared with the eindir energy and
gradient.
A failed centre is stored like a result, and is not evaluated again at the same
bits.

*** =rgpot_hvp_scheme_t=

- Inputs :: none; an enum passed as =int32_t=.
- Units :: none.
- Outputs :: =RGPOT_HVP_AUTO= (0): the analytic callback when one is registered,
  else forward.
  =RGPOT_HVP_FORWARD= (1): =(F(x) - F(x + h u)) |v| / h= with =u = v / |v|=,
  =F(x)= from the cached centre.
  =RGPOT_HVP_CENTRAL= (2): =(F(x - h u) - F(x + h u)) |v| / (2 h)=, two force
  calls.
  =RGPOT_HVP_ANALYTIC= (3): the registered callback.
- Errors :: none; =rgpot_potential_hvp= refuses any other value.

*** =rgpot_hvp_counts_t=

- Inputs :: none; a struct filled by =rgpot_potential_hvp_counts=.
- Units :: none; counts.
- Outputs :: =products=, the products answered, zero-direction products
  included;
  =force_calls=, the force callback invocations for products and centres, failed ones included; =centre_reused=,
  the requests of =rgpot_potential_hvp= and =rgpot_potential_hvp_centre=
  answered from the cached centre; =analytic=, the products the analytic
  callback answered.
- Errors :: none.

                        const rgpot_force_input_t *input, int k,
                        const double *const *q, double *hq) {

  }
  return s;

** Taylor jets

A jet is the list of enclosures =lo_k <= D^k V(x)[v, ..., v] / k! <= hi_k=,
=k = 0..=order=, of the energy along the line =x + t v=.
The bounds are about the real function the potential's source defines with
every literal read as its compiler assigns it, not about the floating-point
program.
A potential with no such enclosure answers =RGPOT_NO_JET= and is never
differenced in its place.
Branches of the source are decided on the enclosure of the tested quantity;
one that contains the threshold is =RGPOT_JET_BRANCH=.
A function or division evaluated outside its domain, or where its recurrence
divides by an enclosure of zero, is =RGPOT_JET_DOMAIN=.
The callback lives behind the handle's =fused_cache= pointer, as the
Hessian-vector callback does.
