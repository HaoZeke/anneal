** C/C++ Tests

#+attr_rgpot: syntax full build and test run
#+begin_src bash
meson setup bbdir -Dwith_tests=true -Dwith_rpc=true --buildtype=debug
meson compile -C bbdir
meson test -C bbdir --print-errorlogs
#+end_src

=cmake= works as well.
CMake's =RGPOT_WITH_CACHE= defaults to =ON= and needs RocksDB, unlike Meson's
=with_cache=false=, so the command below turns it off.
[[file:../../reference/build_options.org][Build options]] lists every Meson and
CMake option.

#+attr_rgpot: syntax full build and test run
#+begin_src bash
cmake -B build-cmake \
  -DRGPOT_BUILD_TESTS=ON \
  -DRGPOT_BUILD_EXAMPLES=ON \
  -DRGPOT_WITH_RPC=ON \
  -DRGPOT_WITH_CACHE=OFF
cmake --build build-cmake
ctest --test-dir build-cmake --output-on-failure
#+end_src

Both register the same tests, except those only meson can run.

*** One test list for meson and CMake

=CppCore/tests/registry.txt= lists every test, one per line: its name, the
features that gate it, its kind, and its timeout, suite, working directory,
environment and flags.
Meson reads the file in =CppCore/meson.build=.
CMake reads it in =cmake/RgpotTestRegistry.cmake=.
=CppCore/tests/tests.cmake= uses that module to register the tests.
A test only meson can run, because it needs an engine, an external program or a
meson-only option, keeps its line with the reason CMake leaves it out.
The comments at the top of the file give the format and each feature.

A unit test, a Fortran program, a neighbour example, a Python script, or a rerun
of a test under other options needs nothing but its line, since both build
systems register those kinds in a loop.
A custom test is registered by hand in each build system, beside its fixtures,
and CMake stops the configuration when it registers a test whose gate does not
hold.

Each build has a =test_list_parity= test, which runs
=CppCore/tests/check_test_registry.py= against the configured build.
It fails when a registered test has no line, when a test whose gate holds is
missing, and when a test's options differ from its line.
=tools/check_test_parity.sh= configures the plain, the RPC and cache, and the
client-only builds with both build systems, without building them.
It runs both checks, then compares the features each build system found and the
tests each registered.
It then passes both =compile_commands.json= files to =tools/check_fp_parity.py=,
which fails when a source both build systems compile gets different contraction
or fast-math flags from each.
The =test_parity= CI job runs it, and =ci_gate= waits on that job.

#+attr_rgpot: syntax configures meson and CMake without building
#+begin_src bash
python3 CppCore/tests/check_test_registry.py lint
pixi run -e mpibld bash tools/check_test_parity.sh
#+end_src

*** Floating-point contraction

=FastNlistTest=, =ReducedPairTest=, =EAMCellVerletTest=, =StreamParityTest=,
=NeighbourLayerTest= and =TersoffSiCTest= compare kernels bit for bit with plain
products and sums.
The kernels are built with contraction off.
The registry gives those six tests =fp_contract=off=, so both build systems
compile them with =-ffp-contract=off= too, neither side fuses, and the compare
stays exact.
A new test of that kind takes the same option.
Outside it, the test can pass on x86-64, where the baseline has no fused
multiply-add, and miss by an ulp on macOS arm64.
To exercise contraction on x86-64, build with Clang at the default debug
buildtype.
GCC does not fuse at =-O0=, and an optimized build folds the Morse test
expressions to constants.

#+attr_rgpot: syntax full build and test run
#+begin_src bash
CXX=clang++ meson setup bbfast -Dwith_tests=true \
  -Dcpp_args='-ffp-contract=fast -mfma'
meson compile -C bbfast
meson test -C bbfast --print-errorlogs
#+end_src

*** OpenMP teams

The OpenMP runtime may start fewer threads than a region asks for: under
=OMP_THREAD_LIMIT=, inside another parallel region, or with dynamic teams.
Every region in the library therefore opens in =CppCore/rgpot/Slices.hpp=.
A caller cuts its work into slices before the region and keeps one buffer per
slice.
=forEachSlice= and =forEachSlicePhase= run each slice once on the threads that
start, several to a thread on a short team, and the caller adds the buffers in
slice order, so the slice count fixes the bits and the team only the speed.
A potential takes its slice count from =teamSize=, which is one below
=kTeamMinAtoms= (8192) atoms, and adds its sums atom by atom in index order, so
neither the slice count nor the team changes its bits.
Ranks that wait for each other use =onFullTeam=, which runs them only when each
has its own thread; otherwise it returns false and the caller does the same work
through =forEachSlice=.
No other library file names a thread number or a team size.
The test suite fails when an OpenMP pragma, a runtime call, the OpenMP header or
the OpenMP macro appears anywhere else in the library sources.
That check is =CppCore/tests/test_openmp_confined.py=.

=ThreadTeamTest= requires the one-thread bits from every threaded potential at
1, 2, 3 and 8 threads and under =rgpot::TeamCap= short teams, dynamic teams and
nested regions, on a system below =kTeamMinAtoms= atoms and on one above it.
Through =rgpot::teamsOpened= it checks that the small system opens no region and
that the large one opens a region in the potential's own sums.
Neighbour tables must keep the bits of the full team under the same teams.
The test suite runs it again under =OMP_THREAD_LIMIT=1= and
=OMP_THREAD_LIMIT=2=, and the =thread_limit= CI job runs the whole suite at both
limits:

#+attr_rgpot: syntax needs a built bbdir
#+begin_src bash
OMP_THREAD_LIMIT=1 meson test -C bbdir --print-errorlogs
OMP_THREAD_LIMIT=2 meson test -C bbdir --print-errorlogs
#+end_src

** Rust Tests

=rust-test-all= enables every feature of =rgpot-core= (=schema=, =profile=,
=rpc=, =cache=, =gen-header=).
=gen-header= makes the build rewrite =rgpot-core/include/rgpot.h=.

#+attr_rgpot: syntax compiles the Rust crate
#+begin_src bash
pixi r rust-test          # default features only
pixi r rust-test-all      # all features
#+end_src

Or directly:

#+attr_rgpot: syntax compiles the Rust crate
#+begin_src bash
cargo nextest run --manifest-path rgpot-core/Cargo.toml
cargo test --doc --manifest-path rgpot-core/Cargo.toml  # doc tests
#+end_src

** NWChem suite (=--suite nwchem=)

The frontend and stub ABI tests build when
=with_tests=true= and =with_rpc=true=.
=meson test= points =RGPOT_NWCHEM_ENGINE= at the in-tree
=libnwchemc_fake_engine.so=.
Cases that need a real NWChem SCF =SKIP= unless
=NWCHEMC_LIBRARY= or =RGPOT_NWCHEMC_ENGINE= names a real =libnwchemc=.
The message ABI test uses a fake =nwchemc_*= shared library and verifies rgpot
passes serialized =NWChemParams= bytes through the =dlopen= boundary.

#+attr_rgpot: syntax full build and test run
#+begin_src bash
meson setup bbdir -Dwith_tests=true -Dwith_rpc=true
meson compile -C bbdir
meson test -C bbdir --suite nwchem --print-errorlogs
#+end_src

See
=CppCore/rgpot/NWChemPot/README.md=; the engine (=libnwchemc=) is built by the split [[https://github.com/OmniPotentRPC/nwchemc][nwchemc]]
project, not by rgpot.

** CPMD suite (=--suite cpmd=)

The frontend and stub ABI tests build when
=with_tests=true= and =with_rpc=true=.
The CPMD frontend loads a split =libcpmdc= engine at runtime via
=CPMDC_LIBRARY=, =RGPOT_CPMDC_ENGINE=, or =RGPOT_CPMD_ENGINE=.
Configure-only Python smokes use =PotentialConfig.cpmd= and do not require a
live engine.

#+attr_rgpot: syntax full build and test run
#+begin_src bash
meson setup bbdir -Dwith_tests=true -Dwith_rpc=true
meson compile -C bbdir
meson test -C bbdir --suite cpmd --print-errorlogs
pixi run -e rpctest python tests/rpc_integ.py --server-bin ./bbdir/CppCore/potserv --cpmd-smoke
#+end_src

See
=CppCore/rgpot/CPMDPot/README.md=; the engine (=libcpmdc=) is built by the split [[https://github.com/OmniPotentRPC/cpmdc][cpmdc]]
project, not by rgpot.
