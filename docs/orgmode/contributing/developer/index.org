* Developer Guide

This section covers the day-to-day development workflow for ~rgpot~.

** Environment Setup

All development is managed through [[https://pixi.sh][pixi]].
Install it first, then:

#+attr_rgpot: syntax installs the pixi environment
#+begin_src bash
pixi install          # default environment (build + test)
pixi shell            # activate the environment
#+end_src

Environments declared in =pixi.toml=:

| Environment | Purpose |
|-------------+---------|
| /(default)/ | Compilers, Meson, CMake, Rust and cargo-nextest, clang-format, cppcheck, cpplint, ccache |
| =rpctest= | RPC integration tests: Cap'n Proto, pycapnp, numpy, ASE, pytest |
| =devbld= | Cap'n Proto and RocksDB (=rpc= and =cache= features) |
| =mpibld= | =devbld= plus Open MPI |
| =docs= | Documentation build (Sphinx, Doxygen, doxyrest, Emacs, pandoc) |
| =cigen= | CI workflow generation (Nickel) |
| =version= | cogapp for the version copies; no default feature |
| =xtbbld=, =tblitebld=, =tbbld= | xtb, tblite, or both |
| =tblite06bld= | tblite 0.6, to compile =TBLitePot= against that API |
| =metatomicbld= | torch, metatomic-torch, metatensor-torch and vesin from PyPI |
| =umaenginebld= | =rpc=, =metatomic= and =xtb= features together |
| =umaexport= | fairchem-core and torch for =scripts/export_uma_aoti.py=; no default feature |
| =xckernel=, =xckerneltest= | libxc and pylibxc; =xckerneltest= adds PySCF |
| =dftd3=, =dftd4=, =dftd= | s-dftd3, dftd4, or both |
| =engines= | LAMMPS, GROMACS, OpenMM, PLUMED and nanobind |
| =eonviz= | eOn and plotting packages; no default feature |

Tasks run with =pixi r <task>=.
A task that belongs to a feature needs that environment, as in
=pixi r -e docs docbld=.
=prek=, =lychee= and =snapper= are not pixi dependencies; install them before
running the tasks that call them.

** One job and one ccache key per pixi environment

Each pixi environment that builds the project runs in its own CI job with its
own compiler-cache key (=ccache-pot-mta-=, =ccache-pot-engine-=, ...).
Two environments in one job share the step environment and the cache directory.
=potctl ci ensure-torch-metatomic= exports the torch and cmake paths of its
environment through =GITHUB_ENV=, so a later step in another environment
inherits them, and a cache entry written against one environment's headers can
satisfy a build against another's.
A =metatomicbld= build followed by an =umaenginebld= build in one job linked
objects compiled against Catch2 3.13 headers with the Catch2 3.16 library of the
second environment, and failed at the link of =plugin_test=.
Add a new environment leg as a new job, not as another step of an existing one.

** Regenerating the C Header

The C header =rgpot-core/include/rgpot.h= is auto-generated by =cbindgen= from
the Rust source.
It is committed to the repository so C/C++ consumers always have a working copy.
After changing the public Rust API:

#+attr_rgpot: syntax rebuilds the Rust crate and rewrites the header
#+begin_src bash
pixi r gen-header
git diff rgpot-core/include/rgpot.h  # review changes
#+end_src

=gen-header= is an optional Cargo feature of =rgpot-core= and is not in its
default features, so neither a normal build nor =cargo publish= rewrites the
header.

cbindgen copies doc comments into the header, so editing the doc comment of an
=extern "C"= function changes it too.
The =rust_tests= CI job runs =tools/check_header_drift.sh=, which rebuilds the
header and fails when git sees a difference.
Commit the header with the change that caused it.

** Building Documentation

Documentation is built with Sphinx and served at
[[https://rgpot.rgoswami.me][rgpot.rgoswami.me]].
It combines:

- *Org-mode pages* (this guide, architecture, changelog) exported to RST
- *C++ API reference* generated by Doxygen + doxyrest
- *Rust API reference* generated by =sphinxcontrib-rust=

=pixi r -e docs doccheck= fails when a pinned citation is dropped, or when an
org page under =docs/orgmode= is not reachable from =docs/orgmode/index.org=.
The design notes copied into the manual are the markdown files under =docs/=
named from that index.

To build locally (=docbld= runs =cargo install sphinx-rustdocgen= on the way):

#+attr_rgpot: syntax full documentation build
#+begin_src bash
pixi r -e docs docbld
# Open docs/build/index.html
#+end_src

To clean generated artifacts:

#+attr_rgpot: syntax deletes generated documentation
#+begin_src bash
pixi r -e docs docdel
#+end_src

** Git hooks (=prek=)

Hooks are configured in =prek.toml= and run with [[https://prek.j178.dev][prek]]
(Rust drop-in for pre-commit).
Prefer =prek= over =pre-commit= / =uvx pre-commit=.

#+attr_rgpot: syntax needs prek installed
#+begin_src bash
# one-time: install shims into .git/hooks
pixi r prek-install   # or: prek install

# run all hooks on the whole tree (CI parity)
pixi r prek           # or: prek run -a --config prek.toml

# validate config only
pixi r prek-validate
#+end_src

The =prek= job of =CI (orchestrator)= runs =prek run -a --config prek.toml= on
pushes and pull requests (not on the weekly schedule).
Org docs also go through =snapper= (semantic line breaks) in the =docs_snapper=
job.
Links are audited separately by the orchestrator =docs_lychee= job, which also
runs on the weekly schedule.
