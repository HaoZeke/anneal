`MorsePot` on a stored neighbour list no longer evaluates each pair from both ends on an OpenMP team, which made 2 threads slower than 1 thread, and `Neighbours::fastTiles` no longer bypasses `walkStored` on stored lists.
From `rgpot::kTeamMinAtoms` atoms and 4096 candidate upper pairs up, `MorsePot` evaluates each upper pair once in a single two-phase region with work-balanced, cache-line-aligned atom slices and vectorised `simd::exp_fixed_n` batches, while keeping the one-thread energy, force, stress and per-atom bits across all thread counts.
