UMA tasks, including `omol`, accept explicit spin `0` without rewriting it to `1`. `rgpot::validate_uma_spin_for_task` in `rgpot/UmaPot/UmaConfig.hpp` now enforces `[0, 100]` for every UMA task, with only negative spins and spins above `100` rejected. The same bounds are enforced in `UmaPot` and `libuma_engine`, while `rgpot_engine_set_charge_spin` still reports unsupported values through `rgpot_engine_last_error`. Also tightened drop-in behavior so `librgpot_gromacs` does not overwrite engine-configured spin with default `CHARGE 0 / MULTIPLICITY 1`, and added explicit tests that Metatomic and Skala reject spin values below `1`.
